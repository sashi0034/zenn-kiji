## 透明度と半透明度の照明

透明で半透明なマテリアルは、シーンにリアリズムと正確さを追加するために重要です。したがって、Filamentは両方のタイプのマテリアルに照明モデルを提供して、アーティストがリアルなシーンを適切に再現できるようにする必要があります。半透明度は、多くの非リアリスティックな設定でも効果的に使用できます。

### 透明度

透明な表面を適切に照明するには、まずマテリアルの不透明度がどのように適用されるかを理解する必要があります。窓を観察すると、拡散反射率が透明であることがわかります。一方、鏡面反射率が明るいほど、窓の不透明度は低く見えます。この効果は図 [cameraTransparency] で見ることができます：シーンはガラス表面に適切に反射されていますが、太陽の鏡面ハイライトは不透明に見えるほど十分に明るいです。

![図 [cameraTransparency]: 照明された表面の透明度が重要な役割を果たす複雑なオブジェクトの例](/images/filament-md-ja/screenshot_camera_transparency.jpg)

![図 [litCar]: 照明された表面の透明度が重要な役割を果たす複雑なオブジェクトの例](/images/filament-md-ja/screenshot_car.jpg)

不透明度を適切に実装するために、事前乗算アルファ形式を使用します。目的の不透明度を $ \alpha_{opacity} $、拡散色を $ \sigma $（線形、非事前乗算）とすると、フラグメントの有効不透明度を計算できます。

$$\begin{align*}
color &= \sigma * \alpha_{opacity} \\
opacity &= \alpha_{opacity}
\end{align*}$$

物理的な解釈は、ソース色のRGBコンポーネントがピクセルによって放出される光の量を定義し、アルファコンポーネントがピクセルの背後にある光がそのピクセルによってどれだけブロックされるかを定義するということです。したがって、次のブレンディング関数を使用する必要があります。

$$\begin{align*}
Blend_{src} &= 1 \\
Blend_{dst} &= 1 - src_{\alpha}
\end{align*}$$

これらの方程式のGLSL実装は、リスト [surfaceTransparency] に示されています。

```glsl
// baseColor has already been premultiplied
vec4 shadeSurface(vec4 baseColor) {
    float alpha = baseColor.a;

    vec3 diffuseColor = evaluateDiffuseLighting();
    vec3 specularColor = evaluateSpecularLighting();    

    return vec4(diffuseColor + specularColor, alpha);
}
```
*リスト [surfaceTransparency]: GLSL での照明された表面の透明度の実装*

### 半透明度

半透明マテリアルは2つのカテゴリに分けることができます。
- 表面半透明度
- ボリューム半透明度

ボリューム半透明度は、パーティクルシステム、たとえば雲や煙を照明するのに役立ちます。表面半透明度は、ワックス、大理石、皮膚など、透過散乱を持つマテリアルを模倣するために使用できます。

## オクルージョン

オクルージョンは、さまざまなスケールでシャドウイングを再現するために使用される重要な暗色化係数です。

**小スケール**

折り目、亀裂、空洞を処理するために使用されるマイクロオクルージョン。

**中スケール**

オブジェクト自身のジオメトリまたは法線マップに焼き込まれたジオメトリ（レンガなど）によるオクルージョンを処理するために使用されるマクロオクルージョン。

**大スケール**

オブジェクト間の接触、またはオブジェクト自身のジオメトリからのオクルージョン。

私たちは現在、マイクロオクルージョンを無視しています。これは、ツールやエンジンで「キャビティマップ」の形式で公開されることがよくあります。Sébastien Lagardeは [#Lagarde14] で、Frostbiteでマイクロオクルージョンがどのように処理されるかについて興味深い議論を提供しています：拡散マイクロオクルージョンは拡散マップに事前焼き込みされ、鏡面マイクロオクルージョンは反射率テクスチャに事前焼き込みされます。私たちのシステムでは、マイクロオクルージョンは単にベースカラーマップに焼き込むことができます。これは、鏡面光がマイクロオクルージョンの影響を受けないことを知って行う必要があります。

中スケールアンビエントオクルージョンは、前述のマテリアルパラメータ化セクションで見たように、マテリアルパラメータとして公開される、アンビエントオクルージョンマップに事前焼き込みされます。

大スケールアンビエントオクルージョンは、*SSAO*（スクリーン空間アンビエントオクルージョン）、*HBAO*（ホライゾンベースアンビエントオクルージョン）などのスクリーン空間技術を使用して計算されることがよくあります。これらの技術は、カメラが表面に十分近い場合、中スケールアンビエントオクルージョンにも寄与できることに注意してください。

**注意**：中スケールと大スケールの両方のオクルージョンを使用する際の過度の暗色化を防ぐために、Lagardeは $min({AO}_{medium}, {AO}_{large})$ の使用を推奨しています。

### 拡散オクルージョン

Morgan McGuireは [#McGuire10] で、物理ベースレンダリングのコンテキストでアンビエントオクルージョンを形式化しています。彼の定式化では、McGuireはアンビエント照明関数 $ L_a $ を定義しており、私たちの場合は球面調和関数でエンコードされています。彼はまた、可視性関数 $V$ を定義しており、方向 $l$ の表面から遮られていない視線がある場合は $V(l)=1$、そうでない場合は0です。

これら2つの関数を使用すると、レンダリング方程式のアンビエント項は式 `diffuseAO` に示すように表現できます。

$$
L(l,v) = \int_{\Omega} f(l,v) L_a(l) V(l) \left< n \cdot l \right> dl
$$

この式は、式 `diffuseAOApprox` に示すように、可視性項を照明関数から分離することで近似できます。

$$
L(l,v) \approx \left( \pi \int_{\Omega} f(l,v) L_a(l) dl \right) \left( \frac{1}{\pi} \int_{\Omega} V(l) \left< n \cdot l \right> dl \right)
$$

この近似は、遠方の光 $ L_a $ が定数で、$f$ がランベルト項である場合にのみ正確です。しかし、McGuireは、両方の関数が球のほとんどで比較的滑らかである場合、この近似は妥当であると述べています。これは、遠方ライトプローブ（IBL）の場合に当てはまります。

この近似の左項は、IBLの事前計算された拡散コンポーネントです。右項は、点のアクセシビリティの割合を示す0〜1のスカラー係数です。その反対は拡散アンビエントオクルージョン項であり、式 `diffuseAOTerm` に示されています。

$$
{AO} = 1 - \frac{1}{\pi} \int_{\Omega} V(l) \left< n \cdot l \right> dl
$$

事前計算された拡散項を使用するため、実行時にシェーディングされた点の正確なアクセシビリティを計算することはできません。事前計算された項でのこの情報不足を補償するために、シェーディングされた点の表面のマテリアルに固有のアンビエントオクルージョン係数を適用することで、入射照明を部分的に再構築します。

実際には、焼き込まれたアンビエントオクルージョンはグレースケールテクスチャとして格納され、他のテクスチャ（ベースカラーや法線など）よりも低解像度であることがよくあります。マテリアルモデルのアンビエントオクルージョンプロパティは、マクロレベルの拡散アンビエントオクルージョンを再現することを意図していることに注意することが重要です。この近似は物理的に正しくありませんが、品質対パフォーマンスの許容できるトレードオフを構成します。

図 [aoComparison] は、拡散アンビエントオクルージョンなしとありの2つの異なるマテリアルを示しています。マテリアルアンビエントオクルージョンが異なるタイル間で発生する自然なシャドウイングを再現するために使用されていることに注意してください。アンビエントオクルージョンがないと、両方のマテリアルは平坦すぎるように見えます。

![図 [aoComparison]: 拡散アンビエントオクルージョンなし（左）とあり（右）のマテリアルの比較](/images/filament-md-ja/screenshot_ao.jpg)

焼き込まれた拡散アンビエントオクルージョンをGLSLシェーダーで適用することは、リスト [bakedDiffuseAO] に示すように簡単です。

```glsl
// diffuse indirect
vec3 indirectDiffuse = max(irradianceSH(n), 0.0) * Fd_Lambert();
// ambient occlusion
indirectDiffuse *= texture2D(aoMap, outUV).r;
```
*リスト [bakedDiffuseAO]: GLSL での焼き込まれた拡散アンビエントオクルージョンの実装*

アンビエントオクルージョン項は間接照明にのみ適用されることに注意してください。

### 鏡面オクルージョン

鏡面マイクロオクルージョンは $f_{0}$ から導出でき、それ自体は拡散色から導出されます。導出は、実世界のマテリアルの反射率が2%未満でないという知識に基づいています。0〜2%の範囲の値は、フレネル項を滑らかに消滅させるために使用される事前焼き込みされた鏡面オクルージョンとして扱うことができます。

```glsl
float f90 = clamp(dot(f0, 50.0 * 0.33), 0.0, 1.0);
// cheap luminance approximation
float f90 = clamp(50.0 * f0.g, 0.0, 1.0);
```
*リスト [specularMicroOcclusion]: GLSL での事前焼き込みされた鏡面オクルージョン*

アンビエントオクルージョンで前述した導出は、ランベルト表面を想定しており、間接拡散照明にのみ有効です。表面アクセシビリティに関する情報の欠如は、間接鏡面照明の再構築に特に有害です。通常、光の漏れとして現れます。

Sébastien Lagardeは [#Lagarde14] で、拡散オクルージョン項から鏡面オクルージョン項を導出する経験的アプローチを提案しています。結果は物理的根拠はありませんが、視覚的に心地よい結果を生成します。彼の定式化の目標は、粗い表面に対しては拡散オクルージョン項を変更せずに返すことです。滑らかな表面の場合、リスト [specularOcclusion] に実装されている定式化は、垂直入射時のオクルージョンの影響を減らし、掠角で増加させます。

```glsl
float computeSpecularAO(float NoV, float ao, float roughness) {
    return clamp(pow(NoV + ao, exp2(-16.0 * roughness - 1.0)) - 1.0 + ao, 0.0, 1.0);
}

// specular indirect
vec3 indirectSpecular = evaluateSpecularIBL(r, perceptualRoughness);
// ambient occlusion
float ao = texture2D(aoMap, outUV).r;
indirectSpecular *= computeSpecularAO(NoV, ao, roughness);
```
*リスト [specularOcclusion]: GLSL でのLagardeの鏡面オクルージョン係数の実装*

鏡面オクルージョン係数は間接照明にのみ適用されることに注意してください。

### ホライゾン鏡面オクルージョン

法線マップを使用する表面の鏡面IBL寄与を計算する際、表面に向かって指す反射ベクトルで終わる可能性があります。この反射ベクトルを直接シェーディングに使用すると、表面が照明されるべきでない場所（不透明な表面を想定）で照明されます。これは、Jeff Russell [#Russell15] によって説明されたシンプルな技術を使用して簡単に最小化できる光の漏れのもう一つの発生です。

キーアイデアは、表面の背後から来る光を遮蔽することです。反射ベクトルと表面の法線間の負のドット積は、表面に向かって指す反射ベクトルを示すため、これは簡単に実現できます。私たちの実装は、リスト [horizonOcclusion] に示されており、Russellのものと似ていますが、アーティスト制御のホライゾンフェーディング係数はありません。

```glsl
// specular indirect
vec3 indirectSpecular = evaluateSpecularIBL(r, perceptualRoughness);

// horizon occlusion with falloff, should be computed for direct specular too
float horizon = min(1.0 + dot(r, n), 1.0);
indirectSpecular *= horizon * horizon;
```
*リスト [horizonOcclusion]: GLSL でのホライゾン鏡面オクルージョンの実装*

ホライゾン鏡面オクルージョンフェーディングは安価ですが、必要に応じてパフォーマンスを向上させるために簡単に省略できます。

## 法線マッピング

法線マップには、ベースマップを使用して高ポリゴンメッシュを低ポリゴンメッシュに置き換えることと、ディテールマップを使用して表面のディテールを追加することの2つの一般的な使用例があります。

タフテッドレザーで覆われた家具を想像してみましょう。タフテッドパターンを正確に表現するためにジオメトリをモデリングすると、三角形が多すぎる必要があるため、代わりに高ポリゴンメッシュを法線マップに焼き込みます。ベースマップが簡略化されたメッシュ（この場合は四角形）に適用されると、図 [normalMapped] の結果が得られます。この効果を作成するために使用されるベースマップは、図 [baseNormalMap] に示されています。

![図 [normalMapped]: 法線マッピングなし（左）とあり（右）の低ポリゴンメッシュ](/images/filament-md-ja/screenshot_normal_mapping.jpg)

![図 [baseNormalMap]: ベースマップとして使用される法線マップ](/images/filament-md-ja/screenshot_normal_map.jpg)

ここで、このベースマップを第2の法線マップと組み合わせたい場合、単純な問題が発生します。たとえば、図 [detailNormalMap] に示されているディテールマップを使用して、レザーにひび割れを追加しましょう。

![図 [detailNormalMap]: ディテールマップとして使用される法線マップ](/images/filament-md-ja/screenshot_normal_map_detail.jpg)

法線マップの性質（タンジェント空間に格納されたXYZコンポーネント）を考えると、線形ブレンディングやオーバーレイブレンディングなどの単純なアプローチが機能しないことはかなり明白です。数学的に正しい技術と、リアルタイムシェーディングに適した近似の2つのより高度な技術を使用します。

### 再方向付け法線マッピング

Colin Barré-BriseboisとStephen Hillは [#Hill12] で、*再方向付け法線マッピング*と呼ばれる数学的に健全なソリューションを提案しています。これは、ベースマップからの法線上にディテールマップの基底を回転させることで構成されます。この技術は、最短アーク四元数に依存して回転を適用しますが、タンジェント空間の特性のおかげで大幅に簡略化されます。

[#Hill12] で説明されている簡略化に従って、リスト [reorientedNormalMapping] に示されているGLSL実装を生成できます。

```glsl
vec3 t = texture(baseMap,   uv).xyz * vec3( 2.0,  2.0, 2.0) + vec3(-1.0, -1.0,  0.0);
vec3 u = texture(detailMap, uv).xyz * vec3(-2.0, -2.0, 2.0) + vec3( 1.0,  1.0, -1.0);
vec3 r = normalize(t * dot(t, u) - u * t.z);
return r;
```
*リスト [reorientedNormalMapping]: GLSL での再方向付け法線マッピングの実装*

この実装は、法線がソーステクスチャに非圧縮で [0..1] 範囲で格納されていることを想定していることに注意してください。

正規化ステップは厳密には必要なく、技術が実行時に使用される場合はスキップできます。その場合、`r` の計算は `t * dot(t, u) / t.z - u` になります。

この技術は以下で説明する技術よりもわずかに高価であるため、主にオフラインで使用します。したがって、2つの法線マップを結合する単純なオフラインツールを提供します。図 [blendedNormalMaps] は、前述のベースマップとディテールマップを使用したツールの出力を示しています。

![図 [blendedNormalMaps]: ブレンドされた法線とディテールマップ（左）と、拡散マップと組み合わせた場合の結果レンダリング（右）](/images/filament-md-ja/screenshot_normal_map_blended.jpg)

### UDNブレンディング

[#Hill12] で説明されているUDNブレンディングと呼ばれる技術は、部分導関数ブレンディング技術のバリアントです。その主な利点は、必要なシェーダー命令の数が少ないことです（リスト [udnBlending] を参照）。平坦なエリアでのディテールの減少につながりますが、ブレンディングを実行時に実行する必要がある場合、UDNブレンディングは興味深いです。

```glsl
vec3 t = texture(baseMap,   uv).xyz * 2.0 - 1.0;
vec3 u = texture(detailMap, uv).xyz * 2.0 - 1.0;
vec3 r = normalize(t.xy + u.xy, t.z);
return r;
```
*リスト [udnBlending]: GLSL でのUDNブレンディングの実装*

結果は再方向付け法線マッピングに視覚的に近いですが、データを注意深く比較すると、UDNは実際にはあまり正確ではないことがわかります。図 [blendedNormalMapsUDN] は、前の例と同じソースデータを使用したUDNブレンディングアプローチの結果を示しています。

![図 [blendedNormalMapsUDN]: UDNブレンディング技術を使用してブレンドされた法線とディテールマップ](/images/filament-md-ja/screenshot_normal_map_blended_udn.jpg)
