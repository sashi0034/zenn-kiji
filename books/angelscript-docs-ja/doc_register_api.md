---
title: "🛠️ 登録可能な要素 (What can be registered)"
---

AngelScript では、スクリプトが自身の外部（アプリケーション側）と対話できるように、開発者が専用のインターフェースを登録（Register）する必要があります。

スクリプトから直接呼び出し可能な[グローバル関数](./doc_register_func)や、グローバル変数としてアクセス可能な[グローバルプロパティ](./doc_register_prop)を登録できます。

より複雑なロジックをスクリプトで記述する場合、組み込みのデータ型を補完するために[独自のオブジェクト型](./doc_register_type)を登録すると非常に便利です。

C++ の世界には文字列型の「決定的な標準」が存在しないため、AngelScript には[組み込みの文字列型](./doc_strings)が用意されていません。その代わり、アプリケーション側で好みの文字列型を登録し、エンジンが文字列のインスタンス化に使用する[文字列ファクトリ](./doc_strings)を指定できるようになっています。

同様に、デフォルトの[組み込み配列型](./doc_arrays)も存在しません。これも、多くの開発者が自身の環境に適した配列実装を利用したいと考えるためです。配列型は[テンプレート](./doc_adv_template)として登録されたのち、[デフォルトの配列型](./doc_arrays)として設定されます。独自の配列型を実装したくない開発者のために、標準の[配列アドオン](./doc_addon#array-テンプレートオブジェクト)が提供されています。

スクリプトクラスが特定のメソッドセットを実装していることを保証したい場合は、[クラスインターフェース (Class interfaces)](./doc_script_global#インターフェース-(interfaces)) を登録できます。アプリケーションからスクリプトクラスを扱う際にインターフェースは便利ですが、インターフェースなしでもアプリケーション側から利用可能なメソッドやプロパティを簡単に列挙できるため、必須ではありません。

コールバックルーチンの実装など、スクリプトからアプリケーションへ関数ポインタを渡すことを許可したい場合は、[関数定義 (Function definitions)](./doc_script_global#funcdef-(関数定義)) を登録できます。

スクリプトの可読性を向上させるために、[列挙型 (Enumeration types)](./doc_script_global#列挙型-(enums)) や [型定義 (typedefs)](./doc_script_global#typedef-(型定義)) を登録することも可能です。
