## グローバル変数 (Variables)

グローバル変数はスクリプト内で宣言でき、そのスクリプトモジュールにアクセスするすべてのコンテキスト間で共有されます。

グローバル変数はすべての関数からアクセス可能です。値はコンパイル時に初期化（またはデフォルト値に設定）され、関数呼び出しをまたいでその変更が保持されます。文字列などのメモリリソースを保持する変数の場合、モジュールが破棄されるかスクリプトエンジンがリセットされる際にそのメモリが解放されます。

```cs
int MyValue = 0;
const uint Flag1 = 0x01;
```

プリミティブ型の変数は、非プリミティブ型（クラスなど）の変数よりも先に初期化されます。これにより、クラスのコンストラクタ内で他のグローバル変数を参照する際、それらが正しい初期値を持っていることが保証されます。ただし、参照先のグローバル変数も非プリミティブ型である場合、初期化の順序は保証されず、初期化中に `null` ポインタ例外が発生するリスクがあります。

グローバル変数の初期化式の中で、他のグローバル変数にアクセスする可能性のある関数を呼び出す際は注意が必要です。コンパイラは依存関係を考慮して初期化順序を調整しようとしますが、複雑な依存関係がある場合は常に成功するとは限りません。初期化前のグローバル変数にアクセスすると、予期しない動作や例外が発生します。

## 仮想プロパティ (Virtual properties)

仮想プロパティは読み書きに特別な動作を持つプロパティです。グローバルに宣言することもできますが、クラスのメンバーとして見られることがほとんどです。

```cs
int prop
{
  get { return SomeValue(); }
  set { UpdateValue(value); }
}
```

参照: [クラスのプロパティ](./doc_script_class_prop)

## インターフェース (Interfaces)

インターフェースはコントラクトのような役割を果たし、インターフェースを実装するクラスはインターフェースで宣言されたメソッドを実装することが保証されます。これにより、特定のインターフェースを実装するオブジェクトへのオブジェクトハンドルを受け取るように関数が指定できるため、ポリモーフィズムの利用が可能になります。その後、関数は動作しているオブジェクトの正確な型を知らなくても、このインターフェースのメソッドを呼び出すことができます。

```cs
// インターフェースの宣言
interface MyInterface
{
  void DoSomething();
}

// インターフェース MyInterface を実装するクラス
class MyClass : MyInterface
{
  void DoSomething()
  {
    // 何かを行います
  }
}
```

クラスは複数のインターフェースを実装できます。すべてのインターフェースをカンマで区切ってリストするだけです。

## インポート (Imports)

メインスクリプトを再コンパイルせずにスクリプトモジュールを動的にロードし、かつモジュール間で相互にやり取りさせたい場合があります。このような状況では、別のモジュールから関数をインポートすることができます。`import` キーワードに続けて関数シグネチャを記述し、最後に提供元となるモジュール名を指定します。

この仕組みにより、インポート対象の関数がコンパイル時点で実際に存在していなくても、スクリプトをコンパイルすることが可能です。アプリケーションは実行時の任意のタイミングで関数をバインド（紐付け）したり、逆にアンバインドしたりできます。

未バインドのインポート関数をスクリプトが呼び出した場合、スクリプト例外が発生して実行が中断されます。

```cs
import void MyFunction(int a, int b) from "Another module";
```

## 列挙型 (Enums)

列挙型 (Enums) は、関連する整数定数のグループに名前を付けて管理するための便利な方法です。マジックナンバーの代わりに名前付きリテラルを使用することでコードの可読性が大幅に向上し、数値の意味をマニュアルで確認する手間が省けます。

列挙型で定義された値以外の数値が変数に代入される可能性も考慮すべきです。変数が予期しない値を保持している場合に備え、`switch` 文などでは常に `default` ケースを用意することを推奨します。

列挙値は列挙型のステートメントにそれらをリストすることで宣言されます。列挙定数に特定の値が与えられない限り、前の定数の値 +1 を取ります。最初の定数は、別途指定されない限り、値 0 を受け取ります。

```cs
enum MyEnum
{
  eValue0,
  eValue2 = 2,
  eValue3,
  eValue200 = eValue2 * 100
}
```

## typedef (型定義)

typedef は他の型のエイリアスを定義するために使用されます。

現在、typedef はプリミティブ型のエイリアスを定義するためにのみ使用できますが、将来のバージョンではすべての種類の型に対してより完全なサポートが行われる予定です。

```cs
typedef float  real32;
typedef double real64;
```

## funcdef (関数定義)

funcdef は、一致するシグネチャを持つ関数へのポインタを格納するための関数シグネチャを定義します。これにより、通常の関数のように呼び出すことができる動的な関数ポインタを作成できます。

```cs
// 関数ポインタの関数シグネチャを定義します
funcdef bool CALLBACK(int, int);
```

参照: より詳細な使い方については [関数ハンドル](./doc_script_datatypes#関数ハンドル-function-handles)

## 名前空間 (Namespaces)

名前空間は大規模なプロジェクトを覚えやすい論理的なユニットに整理するために使用できます。名前空間を使用する場合、プロジェクトの別の部分で異なる名前空間の下に存在する可能性がある名前をエンティティに使用することを心配する必要もありません。

```cs
namespace A
{
  // 名前空間内のエンティティは通常通り互いを認識します
  void function() { variable++; }
  int variable;
}

namespace B
{
  // 異なる名前空間のエンティティはすぐには互いを認識せず、
  // 名前の衝突を引き起こすことなく同じ名前を再利用できます。
  // スコープ演算子を使用することで、望む名前空間のエンティティを
  // 明示的に指定することができます。
  void function() { A::function(); }
}
```

異なる名前空間のエンティティを参照するには、スコープ演算子を使用しなければなりません。ただし、それが親の名前空間であり、且つ子の名前空間が同じエンティティを宣言している場合にのみ必要です。

```cs
int var;
namespace Parent
{
  int var;
  namespace Child
  {
    int var;
    void func()
    {
      // 子の名前空間内のエンティティが同じ名前を使用している場合、
      // 親の名前空間の変数にアクセスするにはスコープを指定する必要があります
      var = Parent::var;

      // グローバルスコープの変数にアクセスするには
      // 名前なしのスコープ演算子を使用します
      Parent::var = ::var;
    }
  }
}

void func()
{
  // ネストされた名前空間の変数にアクセスするには
  // 完全修飾スコープ指定子が必要です
  int var = Parent::Child::var;
}
```

### using namespace

シンボルに常に名前空間のプレフィックスを付けることを避けるために、`using namespace` を使用してコンパイラが特定の名前空間でもシンボルを検索するよう指示することもできます。

```cs
namespace test
{
  void func() {}
}
using namespace test;
void main()
{
  func(); // 関数は test 名前空間内で見つかります
}
```

`using namespace` がグローバルに、または名前空間内で使用される場合、指定された名前空間のシンボルはその外包名前空間全体で可視になります。

参照: [ステートメント 'using namespace'](./doc_script_statement#using-namespace-ステートメント-using-namespace)
