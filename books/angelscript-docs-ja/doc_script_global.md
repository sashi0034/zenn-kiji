## グローバル変数 (Variables)

グローバル変数はスクリプトで宣言でき、そのスクリプトモジュールにアクセスするすべてのコンテキストで共有されます。

このようにグローバルに宣言された変数はすべての関数からアクセスできます。変数の値はコンパイル時に初期化され、呼び出し間でその変更は維持されます。グローバル変数がメモリリソース（例えば文字列）を保持している場合、そのメモリはモジュールが破棄されるかスクリプトエンジンがリセットされた際に解放されます。

```angelscript
int MyValue = 0;
const uint Flag1 = 0x01;
```

プリミティブ型の変数は非プリミティブ型の変数より前に初期化されます。これにより、クラスのコンストラクタが他のグローバル変数に対して正しい初期値ですでにアクセスできるようになります。例外として、他のグローバル変数も非プリミティブ型である場合、どの変数が最初に初期化されるかの保証はなく、初期化中に null ポインタ例外が発生する可能性があります。

グローバル変数の初期化式内からグローバル変数にアクセスする可能性のある関数を呼び出す際は注意が必要です。コンパイラはグローバル変数を必要な順序で初期化しようとしますが、常に成功するとは限りません。まだ初期化されていないグローバル変数に関数がアクセスした場合、予測不可能な動作または null ポインタ例外が発生します。

## 仮想プロパティ (Virtual properties)

仮想プロパティは読み書きに特別な動作を持つプロパティです。グローバルに宣言することもできますが、クラスのメンバーとして見られることがほとんどです。

```angelscript
int prop
{
  get { return SomeValue(); }
  set { UpdateValue(value); }
}
```

参照: [クラスのプロパティ](./doc_script_class_prop)

## インターフェース (Interfaces)

インターフェースはコントラクトのような役割を果たし、インターフェースを実装するクラスはインターフェースで宣言されたメソッドを実装することが保証されます。これにより、特定のインターフェースを実装するオブジェクトへのオブジェクトハンドルを受け取るように関数が指定できるため、ポリモーフィズムの利用が可能になります。その後、関数は動作しているオブジェクトの正確な型を知らなくても、このインターフェースのメソッドを呼び出すことができます。

```angelscript
// インターフェースの宣言
interface MyInterface
{
  void DoSomething();
}

// インターフェース MyInterface を実装するクラス
class MyClass : MyInterface
{
  void DoSomething()
  {
    // 何かを行います
  }
}
```

クラスは複数のインターフェースを実装できます。すべてのインターフェースをカンマで区切ってリストするだけです。

## インポート (Imports)

メインスクリプトを再コンパイルせずにスクリプトモジュールを動的にロードしながら、モジュール同士が互いに対話できるようにする必要がある場合があります。そのような場合、スクリプトは別のモジュールから関数をインポートすることができます。この宣言は `import` キーワードを使用して書かれ、関数シグネチャが続き、そしてどのモジュールからインポートするかを指定します。

これにより、これらのインポートされた関数をコンパイル時に実際に利用可能でなくてもスクリプトをコンパイルできます。アプリケーションは後で関数をバインドし、再びアンバインドすることもできます。

まだバインドされていないインポートされた関数をスクリプトが呼び出した場合、スクリプト例外でスクリプトが中断されます。

```angelscript
import void MyFunction(int a, int b) from "Another module";
```

## 列挙型 (Enums)

列挙型は、数値定数の代わりにスクリプト全体で名前付きリテラルとして使用できる整数定数のファミリーを登録する便利な方法です。列挙型を使用することでコードの可読性が向上することが多く、名前付きリテラルは通常、読み手がマニュアルで数値の意味を調べなくても意図が何かを説明してくれます。

列挙型が有効な値をリストしていても、列挙型の変数が宣言されたリストの値のみを含むとは限りません。変数が予期しない値を保持している場合に備えて、常にデフォルトのアクションを持つようにしてください。

列挙値は列挙型のステートメントにそれらをリストすることで宣言されます。列挙定数に特定の値が与えられない限り、前の定数の値 +1 を取ります。最初の定数は、別途指定されない限り、値 0 を受け取ります。

```angelscript
enum MyEnum
{
  eValue0,
  eValue2 = 2,
  eValue3,
  eValue200 = eValue2 * 100
}
```

## typedef (型定義)

typedef は他の型のエイリアスを定義するために使用されます。

現在、typedef はプリミティブ型のエイリアスを定義するためにのみ使用できますが、将来のバージョンではすべての種類の型に対してより完全なサポートが行われる予定です。

```angelscript
typedef float  real32;
typedef double real64;
```

## funcdef (関数定義)

funcdef は、一致するシグネチャを持つ関数へのポインタを格納するために使用される関数シグネチャを定義するために使用されます。これにより、後で通常の関数呼び出しとして呼び出すことができる動的なポインタを格納できる関数ポインタを作成することができます。

```angelscript
// 関数ポインタの関数シグネチャを定義します
funcdef bool CALLBACK(int, int);
```

参照: より詳細な使い方については [関数ハンドル](./doc_script_datatypes)

## 名前空間 (Namespaces)

名前空間は大規模なプロジェクトを覚えやすい論理的なユニットに整理するために使用できます。名前空間を使用する場合、プロジェクトの別の部分で異なる名前空間の下に存在する可能性がある名前をエンティティに使用することを心配する必要もありません。

```angelscript
namespace A
{
  // 名前空間内のエンティティは通常通り互いを認識します
  void function() { variable++; }
  int variable;
}

namespace B
{
  // 異なる名前空間のエンティティはすぐには互いを認識せず、
  // 名前の衝突を引き起こすことなく同じ名前を再利用できます。
  // スコープ演算子を使用することで、望む名前空間のエンティティを
  // 明示的に指定することができます。
  void function() { A::function(); }
}
```

異なる名前空間のエンティティを参照するには、スコープ演算子を使用しなければなりません。ただし、それが親の名前空間であり、且つ子の名前空間が同じエンティティを宣言している場合にのみ必要です。

```angelscript
int var;
namespace Parent
{
  int var;
  namespace Child
  {
    int var;
    void func()
    {
      // 子の名前空間内のエンティティが同じ名前を使用している場合、
      // 親の名前空間の変数にアクセスするにはスコープを指定する必要があります
      var = Parent::var;

      // グローバルスコープの変数にアクセスするには
      // 名前なしのスコープ演算子を使用します
      Parent::var = ::var;
    }
  }
}

void func()
{
  // ネストされた名前空間の変数にアクセスするには
  // 完全修飾スコープ指定子が必要です
  int var = Parent::Child::var;
}
```

### using namespace

シンボルに常に名前空間のプレフィックスを付けることを避けるために、`using namespace` を使用してコンパイラが特定の名前空間でもシンボルを検索するよう指示することもできます。

```angelscript
namespace test
{
  void func() {}
}
using namespace test;
void main()
{
  func(); // 関数は test 名前空間内で見つかります
}
```

`using namespace` がグローバルに、または名前空間内で使用される場合、指定された名前空間のシンボルはその外包名前空間全体で可視になります。

参照: [ステートメント 'using namespace'](./doc_script_statement)
