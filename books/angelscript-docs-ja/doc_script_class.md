## クラスの概要 (Script class overview)

クラスを使用することで、プロパティ（データ）のグループと、それらを操作するための [メソッド](#クラスのメソッド-(class-methods)) を備えた新しいデータ型を定義できます。

スクリプトクラスは **参照型** です。これは、同じオブジェクトインスタンスに対して複数の参照や [ハンドル](./doc_script_handle) を保持できることを意味します。クラスは自動メモリ管理（参照カウントおよびガベージコレクション）を使用するため、オブジェクトへのすべての参照がなくなった時に初めて破棄されます。

```cs
// クラスの宣言
class MyClass
{
  // クラスのメソッド
  void DoSomething() {}

  // クラスのプロパティ
  int a;
  int b;
}
```

クラスは [演算子をオーバーロード](./doc_script_class_ops) するための特定のメソッドを実装することができます。これにより、各関数を明示的に命名する必要がなくなり、オブジェクトインスタンスを式で使用する方法を簡素化できます（例えば、`opAdd` メソッドは `+` 演算子に変換されます）。

もう一つの便利な機能は [プロパティアクセサー](./doc_script_class_prop) を実装する機能です。これは仮想プロパティ（プロパティのように見えるが実際にはない）を提供するためや、プロパティにアクセスするたびに実行しなければならない特定のルーティンを実装するために使用できます。

スクリプトクラスは他のクラスを [継承](#継承とポリモーフィズム-(inheritance-and-polymorphism)) し、[インターフェース](./doc_script_global#インターフェース-(interfaces)) を実装することもできます。

## コンストラクタ (Class constructors)

クラスのコンストラクタは、そのクラスの新しいインスタンスを生成する際に呼び出される特別なメソッドです。コンストラクタの定義は必須ではありませんが、定義しておくことで、インスタンス化の直後にプロパティを手動で設定する手間が省け、クラスが使いやすくなります。

コンストラクタは戻り値の型を持たず、クラス名と同じ名前で宣言します。引数リストが異なる複数のコンストラクタを定義して、さまざまな初期化方法を提供することが可能です。

```cs
class MyClass
{
  // デフォルトコンストラクタを実装します
  MyClass()
  {
  }

  // コピーコンストラクタを実装します
  MyClass(const MyClass &inout other)
  {
    // 他のインスタンスの値をコピーします
  }

  // 異なるパラメータリストを持つ他のコンストラクタを実装します
  MyClass(int a, string b) {}
  MyClass(float x, float y, float z) {}

  // 変換コンストラクタを実装します
  // 2番目は明示的にのみ使用できます
  MyClass(int a) {}
  MyClass(string a) explicit {}
}
```

コピーコンストラクタは、オブジェクトの複製を行う際にコンパイラがより効率的なコードを生成するために利用する特殊なコンストラクタです。コピーコンストラクタがない場合、コンパイラは「デフォルトコンストラクタでインスタンスを生成した後に [opAssign](./doc_script_class_ops) メソッドで各属性をコピーする」という手順を踏むことになります。

引数を1つだけ取るコンストラクタは、[型変換](./doc_script_expr#型変換-(type-conversions)) に利用できます。デフォルトでは、コンパイラが必要に応じてこれらのコンストラクタを使い暗黙的な型変換を行いますが、これを防ぎたい場合は、コンストラクタの宣言に `explicit` 修飾子を付けます。

1つのコンストラクタから別のコンストラクタを直接呼び出すことはできません。共通の初期化処理を行いたい場合は、専用のプライベートメソッドなどを用意して共有してください。

### 自動生成されるコンストラクタ (Auto-generated constructors)

コンパイラは一部のケースで自動的にデフォルトコンストラクタとコピーコンストラクタを生成します。

デフォルトコンストラクタは、他のコンストラクタが明示的に宣言されていない場合に自動的に生成されます。このコンストラクタはすべてのオブジェクトメンバーのデフォルトコンストラクタを単純に呼び出し、すべてのハンドルを null に設定します（ただし、メンバーに明示的な初期化がある場合はそれが実行されます）。

コピーコンストラクタは、コピーコンストラクタが明示的に宣言されていない場合に自動的に生成されます。このコンストラクタは各メンバーをコピー構築しようとします。コピーコンストラクタが利用可能でない場合は、デフォルト構築してから代入を行います。

自動生成されるコンストラクタが望ましくない場合は、それらを削除済みとしてフラグを立てることで明示的に除外できます：

```cs
class MyClass
{
  MyClass() delete;
  MyClass(const MyClass &inout) delete;
}
```

## デストラクタ (Class destructor)

AngelScript はデフォルトでオブジェクトが破棄される際にオブジェクトが保持するリソースを解放するため、通常クラスのデストラクタを実装する必要はありません。しかし、オブジェクトの破棄の一部としてより明示的なクリーンアップルーティンを実行しなければならない状況があるかもしれません。

デストラクタはコンストラクタと同様に宣言されますが、`~` 記号（ビット否定演算子としても知られる）を前置しなければなりません。

```cs
class MyClass
{
  // 明示的なクリーンアップが必要な場合はデストラクタを実装します
  ~MyClass()
  {
    // 明示的なクリーンアップをここで行います
  }
}
```

AngelScript はガベージコレクションを使用した自動メモリ管理を使用するため、デストラクタがいつ実行されるかを常に予測しやすいわけではありません。AngelScript は、デストラクタの実行中に参照を追加してオブジェクトが「復活」した場合でも、デストラクタを1回のみ呼び出します。

デストラクタを直接呼び出すことはできません。クリーンアップを直接呼び出す必要がある場合は、そのためのパブリックメソッドを実装すべきです。

## クラスのメソッド (Class methods)

クラスのメソッドは [グローバル関数](./doc_script_function) と同様に実装されますが、クラスのメソッドはクラスのインスタンスのプロパティに直接、またはローカル変数が同じ名前を持つ場合は `this` キーワードを通じてアクセスできるという点が追加されています。

```cs
// クラスの宣言
class MyClass
{
  // クラスのメソッド
  void DoSomething()
  {
    // クラスのプロパティには直接アクセスできます
    a *= 2;

    // ローカル変数の宣言によってクラスのプロパティが隠される場合があります
    int b = 42;

    // その場合、クラスのプロパティには明示的にアクセスしなければなりません
    this.b = b;
  }

  // クラスのプロパティ
  int a;
  int b;
}
```

### const メソッド (Const methods)

クラスは「const オーバーロード」という新たな [関数オーバーロード](./doc_script_function) の形態を提供します。クラスメソッドが読み取り専用（const）の参照やハンドルを通じて呼び出される場合、`const` 修飾子が付いたメソッドのみが実行可能です。書き込み可能な参照やハンドルの場合は両方のメソッドが候補になりますが、両方が一致する場合は非 const 版が優先されます。

```cs
class CMyClass
{
  int method()       { a++; return a; } 
  int method() const {      return a; }
  int a;
}
void Function()
{
   CMyClass o;
   const CMyClass @h = o;

   o.method(); // メンバー a をインクリメントする非 const バージョンを呼び出します
   h.method(); // メンバー a をインクリメントしない const バージョンを呼び出します
}
```

## 継承とポリモーフィズム (Inheritance and polymorphism)

AngelScript は単一継承をサポートしており、派生クラスは基底クラスのプロパティとメソッドを引き継ぎます。多重継承はサポートされていませんが、[インターフェース](./doc_script_global#インターフェース-(interfaces)) によるポリモーフィズムや、[ミックスインクラス](./doc_script_mixin) によるコードの再利用が可能です。

AngelScript のクラスメソッドはすべて仮想関数（virtual）であるため、明示的に指定する必要はありません。派生クラスでメソッドをオーバーライドした際、スコープ解決演算子（`Base::Method`）を使って基底クラスのメソッドを明示的に呼び出すことで、元の機能を拡張できます。派生クラスのコンストラクタでは、`super` キーワードを使用して基底クラスのコンストラクタを呼び出します。手動で呼び出さない場合、コンパイラは自動的にデフォルトコンストラクタの呼び出しを先頭に挿入します。

```cs
// 派生クラス
class MyDerived : MyBase
{
  // デフォルトコンストラクタ
  MyDerived()
  {
    // 基底クラスの非デフォルトコンストラクタを呼び出します
    super(10);
    
    b = 0;
  }
  
  // 仮想メソッドのオーバーロード
  void DoSomething()
  {
    // 基底クラスの実装を呼び出します
    MyBase::DoSomething();
    
    // さらに何かを行います
    b = a;
  }
  
  int b;
}
```

他のクラスから派生したクラスは暗黙的に基底クラスにキャストできます。インターフェースを実装するクラスでも同様です。逆方向にはコンパイル時にキャストが有効かどうかが分からないため、 [明示的なキャスト](./doc_script_expr#型変換-(type-conversions)) が必要です。

```cs
class A {}
class B : A {}
void Foo()
{
  A @handle_to_A;
  B @handle_to_B;

  @handle_to_A = A(); // OK
  @handle_to_A = B(); // OK。参照は暗黙的に A@ にキャストされます

  @handle_to_B = A(); // コンパイルエラー
  @handle_to_B = B(); // OK

  @handle_to_A = handle_to_B; // OK。参照は暗黙的に A@ にキャストされます
  @handle_to_B = handle_to_A; // コンパイルエラー

  @handle_to_B = cast<B>(handle_to_A); // OK。ただし、handle_to_A のオブジェクトが実際に B の
                                       // インスタンスでない場合、明示的キャストは null を返します
}
```


### final, abstract, override

クラスを `final` としてマークして、そのクラスの継承を防ぐことができます。これはオプションの機能で、多くのクラスがあり全クラスの正しい使用を手動で制御することが難しい大規模なプロジェクトで主に使用されます。クラスの個々のクラスメソッドを `final` としてマークすることも可能で、その場合クラスから継承することはできますが、final としてマークされたメソッドはオーバーライドできません。

クラスをマークするために使用できるもう一つのキーワードは `abstract` です。抽象クラスはインスタンス化できませんが、それから派生することができます。抽象クラスは、共通の基底クラスから派生させることでクラスのファミリーを作成したいが、基底クラス自体をインスタンス化させたくない場合に最もよく使用されます。

```cs
// 継承できない final クラス
final class MyFinal
{
  MyFinal() {}
  void Method() {}
}

// 個々のメソッドが final のクラス
class MyPartiallyFinal
{
  // オーバーライドできない final メソッド
  void Method1() final {}

  // 派生クラスでオーバーライドできる通常のメソッド
  void Method2() {}
}

// 抽象クラス
abstract class MyAbstractBase {}
```

クラスを派生させる際に、メソッドが継承された基底クラスのメソッドをオーバーライドすることを意図していることをコンパイラに伝えることができます。これを行い基底クラスに一致するメソッドがない場合、コンパイラはエラーを発行します。これは基底クラスが変更されるが、派生クラスを更新するのを忘れてしまう可能性がある大規模なプロジェクトでエラーを捕捉するのに特に有用です。

```cs
class MyBase
{
  void Method() {}
  void Method(int) {}
}

class MyDerived : MyBase
{
  void Method() override {}      // OK。メソッドは基底クラスのメソッドをオーバーライドしています
  void Method(float) override {} // NG。メソッドは基底クラスのメソッドをオーバーライドしていません
}
```

## プロテクトとプライベートなクラスメンバー (Protected and private class members)

クラスのメンバーはアクセスできる場所を制御するために `protected` または `private` として宣言できます。プロテクトされたメンバーはクラスの外からアクセスできません。プライベートなメンバーはさらに、派生クラスからもアクセスできません。

```cs
// プライベートなメンバーを持つクラス
class MyBase
{
  // 以下はパブリックなメンバーです
  void PublicFunc()
  {
    // クラスは自身のプロテクトとプライベートなメンバーにアクセスできます
    ProtectedProp = 0; // OK
    ProtectedFunc();   // OK
    PrivateProp = 0;   // OK
    PrivateFunc();     // OK
  }   

  int PublicProp;

  // 以下はプロテクトなメンバーです
  protected void ProtectedFunc() {}
  protected int ProtectedProp;

  // 以下はプライベートなメンバーです
  private void PrivateFunc() {} 
  private int PrivateProp;
}

class MyDerived : MyBase
{
  void Func()
  {
    // 派生クラスは基底クラスのプロテクトなメンバーにアクセスできますが、
    // プライベートなメンバーにはアクセスできません
    ProtectedProp = 1; // OK
    ProtectedFunc();   // OK
    PrivateProp = 1;   // エラー
    PrivateFunc();     // エラー
  }
}
```

## クラスメンバーの初期化 (Initialization of class members)

クラスメンバーが初期化される順序は、継承を使用する場合やメンバーの初期化を宣言に直接定義する場合に重要になります。初期化前にメンバーにアクセスすると、スクリプトの実行を中断する null ハンドルアクセス例外が発生する可能性があります。

単純なクラスの場合、メンバーが初期化される順序はそれらが宣言された順序と同じです。メンバーの宣言に明示的な初期化が与えられている場合、これらのメンバーは最後に初期化されます。

```cs
// このクラスの初期化順序は a, c, b, d となります
class Foo
{
  string a;
  string b = a;
  string c;
  string d = b;
}
```

継承が使用される場合、明示的な初期化がない派生クラスのメンバーは基底クラスのメンバーの前に初期化され、明示的な初期化があるメンバーは基底クラスのメンバーの後に初期化されます。

```cs
// このクラスの初期化順序は a, b となります
class Bar
{
  string a;
  string b = a;
}

// このクラスの初期化順序は d, a, b, c となります
class Foo : Bar
{
  string c = a;
  string d;
}
```

この初期化順序は、メンバーが初期化される前にアクセスされることによる問題の多くを避けるために選択されています。

すべてのメンバーは定義されたコンストラクタの開始直後に初期化されるため、コンストラクタ内の残りのコードは安心してメンバーにアクセスできます。例外は、コンストラクタが `super()` を呼び出して基底クラスを明示的に初期化する場合、またはコンストラクタの本体内でメンバーの初期化を上書きする場合です。この場合、本体内で明示的に初期化されるメンバーは、そのステートメントに到達するまで未初期化のままとなります。

```cs
class Bar
{
  Bar(string val) { a = val; }
  string a;
}

class Foo : Bar
{
  Foo()
  {
    // b が最初に初期化されます
    // 後で明示的に初期化しない場合、ここで c が初期化されますが、
    // まだ super() が呼び出されていないため null ポインタ例外が発生します。

    super(b); // この呼び出しで a が初期化されます

    c = a; // 基底クラスの後に c を明示的に初期化して、null ポインタ例外を避けます
  }
  
  string b;
  string c = a;
}
```

メンバーは条件文の中で初期化することもできます。その場合、両方の条件でメンバーを初期化しなければなりません。

```cs
class Foo
{
  Foo(int a)
  {
    if( a == 0 ) // メンバーが条件内で初期化される場合、両方の分岐で初期化が必要です
      d = 'foo';
    else
      d = 'bar';
  }
  
  string d = 'default';
}
```

:::message
コンストラクタや初期化がクラスのメソッドを呼び出す場合に注意してください。クラスのメソッドは派生クラスでオーバーライドできるため、基底クラスが派生クラスのメンバーが初期化される前に誤ってアクセスしてしまう可能性があります。

```cs
class Bar
{
  Bar()
  {
    DoSomething();
  }

  void DoSomething() {}
}

// このクラスは null ハンドル例外を引き起こします。なぜなら、Bar のコンストラクタが
// msg メンバーが初期化される前にアクセスする DoSomething() メソッドを呼び出すからです。
class Foo : Bar
{
  string msg = 'hello';
  void DoSomething()
  {
    print(msg);
  }
}
```
:::
