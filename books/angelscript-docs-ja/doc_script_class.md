## クラスの概要 (Script class overview)

クラスを使用することで、スクリプトライターはプロパティのグループと、それらを操作するための [メソッド](./doc_script_class) を保持する新しいデータ型を宣言できます。

スクリプトクラスは参照型であり、同じオブジェクトインスタンスに対して複数の参照や [ハンドル](./doc_script_handle) を保持することができます。クラスは自動的なメモリ管理を使用するため、オブジェクトインスタンスへの最後の参照がクリアされた時にのみ破棄されます。

```angelscript
// クラスの宣言
class MyClass
{
  // クラスのメソッド
  void DoSomething() {}

  // クラスのプロパティ
  int a;
  int b;
}
```

クラスは [演算子をオーバーロード](./doc_script_class_ops) するための特定のメソッドを実装することができます。これにより、各関数を明示的に命名する必要がなくなり、オブジェクトインスタンスを式で使用する方法を簡素化できます（例えば、`opAdd` メソッドは `+` 演算子に変換されます）。

もう一つの便利な機能は [プロパティアクセサー](./doc_script_class_prop) を実装する機能です。これは仮想プロパティ（プロパティのように見えるが実際にはない）を提供するためや、プロパティにアクセスするたびに実行しなければならない特定のルーティンを実装するために使用できます。

スクリプトクラスは他のクラスを [継承](./doc_script_class) し、[インターフェース](./doc_global_interface) を実装することもできます。

## コンストラクタ (Class constructors)

クラスのコンストラクタは、クラスの新しいインスタンスを作成するために使用される特定のメソッドです。クラスがコンストラクタを宣言する必要はありませんが、そうすることでクラスを使いやすくなります。クラスをインスタンス化してからプロパティを手動で設定する必要がないからです。

コンストラクタは戻り値の型なしで宣言され、クラス自体と同じ名前を持たなければなりません。異なる初期化の形式のために、異なるパラメータリストを持つ複数のコンストラクタを実装することができます。

```angelscript
class MyClass
{
  // デフォルトコンストラクタを実装します
  MyClass()
  {
  }

  // コピーコンストラクタを実装します
  MyClass(const MyClass &inout other)
  {
    // 他のインスタンスの値をコピーします
  }

  // 異なるパラメータリストを持つ他のコンストラクタを実装します
  MyClass(int a, string b) {}
  MyClass(float x, float y, float z) {}

  // 変換コンストラクタを実装します
  // 2番目は明示的にのみ使用できます
  MyClass(int a) {}
  MyClass(string a) explicit {}
}
```

コピーコンストラクタは、オブジェクトのコピーを作成しなければならない時に、コンパイラがより効率的なコードを構築するために使用できる特定のコンストラクタです。コピーコンストラクタがない場合、コンパイラはデフォルトコンストラクタを使用してコピーをインスタンス化し、その後 [opAssign](#) メソッドで属性をコピーすることを余儀なくされます。

1つの引数を取るコンストラクタは [型変換](./doc_script_class) で使用することができます。デフォルトでは、コンパイラは必要に応じて暗黙的な変換を実行するためにこれらを使用することができます。それが望ましくない場合は、コンストラクタの後に `explicit` デコレータを追加することでこれを禁止することができます。

1 つのコンストラクタは別のコンストラクタを呼び出すことができません。コンストラクタで実装を共有したい場合は、その目的のための特定のメソッドを使用してください。

### 自動生成されるコンストラクタ (Auto-generated constructors)

コンパイラは一部のケースで自動的にデフォルトコンストラクタとコピーコンストラクタを生成します。

デフォルトコンストラクタは、他のコンストラクタが明示的に宣言されていない場合に自動的に生成されます。このコンストラクタはすべてのオブジェクトメンバーのデフォルトコンストラクタを単純に呼び出し、すべてのハンドルを null に設定します（ただし、メンバーに明示的な初期化がある場合はそれが実行されます）。

コピーコンストラクタは、コピーコンストラクタが明示的に宣言されていない場合に自動的に生成されます。このコンストラクタは各メンバーをコピー構築しようとします。コピーコンストラクタが利用可能でない場合は、デフォルト構築してから代入を行います。

自動生成されるコンストラクタが望ましくない場合は、それらを削除済みとしてフラグを立てることで明示的に除外できます：

```angelscript
class MyClass
{
  MyClass() delete;
  MyClass(const MyClass &inout) delete;
}
```

## デストラクタ (Class destructor)

AngelScript はデフォルトでオブジェクトが破棄される際にオブジェクトが保持するリソースを解放するため、通常クラスのデストラクタを実装する必要はありません。しかし、オブジェクトの破棄の一部としてより明示的なクリーンアップルーティンを実行しなければならない状況があるかもしれません。

デストラクタはコンストラクタと同様に宣言されますが、`~` 記号（ビット否定演算子としても知られる）を前置しなければなりません。

```angelscript
class MyClass
{
  // 明示的なクリーンアップが必要な場合はデストラクタを実装します
  ~MyClass()
  {
    // 明示的なクリーンアップをここで行います
  }
}
```

AngelScript はガベージコレクションを使用した自動メモリ管理を使用するため、デストラクタがいつ実行されるかを常に予測しやすいわけではありません。AngelScript は、デストラクタの実行中に参照を追加してオブジェクトが「復活」した場合でも、デストラクタを1回のみ呼び出します。

デストラクタを直接呼び出すことはできません。クリーンアップを直接呼び出す必要がある場合は、そのためのパブリックメソッドを実装すべきです。

## クラスのメソッド (Class methods)

クラスのメソッドは [グローバル関数](./doc_script_function) と同様に実装されますが、クラスのメソッドはクラスのインスタンスのプロパティに直接、またはローカル変数が同じ名前を持つ場合は `this` キーワードを通じてアクセスできるという点が追加されています。

```angelscript
// クラスの宣言
class MyClass
{
  // クラスのメソッド
  void DoSomething()
  {
    // クラスのプロパティには直接アクセスできます
    a *= 2;

    // ローカル変数の宣言によってクラスのプロパティが隠される場合があります
    int b = 42;

    // その場合、クラスのプロパティには明示的にアクセスしなければなりません
    this.b = b;
  }

  // クラスのプロパティ
  int a;
  int b;
}
```

### const メソッド (Const methods)

クラスは新しいタイプの [関数オーバーロード](./doc_script_function)、つまり const オーバーロードを追加します。クラスのメソッドが読み取り専用の参照またはハンドルを通じてアクセスされる場合、`const` としてマークされているメソッドのみが呼び出せます。参照またはハンドルが書き込み可能な場合、両方のタイプが呼び出せますが、両方が一致する場合は非 const バージョンが優先されます。

```angelscript
class CMyClass
{
  int method()       { a++; return a; } 
  int method() const {      return a; }
  int a;
}
void Function()
{
   CMyClass o;
   const CMyClass @h = o;

   o.method(); // メンバー a をインクリメントする非 const バージョンを呼び出します
   h.method(); // メンバー a をインクリメントしない const バージョンを呼び出します
}
```

## 継承とポリモーフィズム (Inheritance and polymorphism)

AngelScript は単一継承をサポートし、派生クラスは基底クラスのプロパティとメソッドを継承します。多重継承はサポートされていませんが、[インターフェース](./doc_global_interface) を実装することでポリモーフィズムがサポートされ、[ミックスインクラス](./doc_script_mixin) を含めることでコードの再利用が提供されます。

すべてのクラスメソッドは仮想であるため、これを手動で指定する必要はありません。派生クラスが実装をオーバーライドする場合は、スコープ解決演算子を使用して基底クラスのメソッドを明示的に呼び出すことで元の実装を拡張することができます。派生クラスのコンストラクタを実装する際、`super` キーワードを使用して基底クラスのコンストラクタを呼び出します。基底クラスのコンストラクタが手動で呼び出されない場合、コンパイラは自動的に最初にデフォルトコンストラクタへの呼び出しを挿入します。

```angelscript
// 派生クラス
class MyDerived : MyBase
{
  // デフォルトコンストラクタ
  MyDerived()
  {
    // 基底クラスの非デフォルトコンストラクタを呼び出します
    super(10);
    
    b = 0;
  }
  
  // 仮想メソッドのオーバーロード
  void DoSomething()
  {
    // 基底クラスの実装を呼び出します
    MyBase::DoSomething();
    
    // さらに何かを行います
    b = a;
  }
  
  int b;
}
```

他のクラスから派生したクラスは暗黙的に基底クラスにキャストできます。インターフェースを実装するクラスでも同様です。逆方向にはコンパイル時にキャストが有効かどうかが分からないため、 [明示的なキャスト](./doc_script_class) が必要です。

### final, abstract, override

クラスを `final` としてマークして、そのクラスの継承を防ぐことができます。これはオプションの機能で、多くのクラスがあり全クラスの正しい使用を手動で制御することが難しい大規模なプロジェクトで主に使用されます。クラスの個々のクラスメソッドを `final` としてマークすることも可能で、その場合クラスから継承することはできますが、final としてマークされたメソッドはオーバーライドできません。

クラスをマークするために使用できるもう一つのキーワードは `abstract` です。抽象クラスはインスタンス化できませんが、それから派生することができます。抽象クラスは、共通の基底クラスから派生させることでクラスのファミリーを作成したいが、基底クラス自体をインスタンス化させたくない場合に最もよく使用されます。

```angelscript
// 継承できない final クラス
final class MyFinal
{
  MyFinal() {}
  void Method() {}
}

// 個々のメソッドが final のクラス
class MyPartiallyFinal
{
  // オーバーライドできない final メソッド
  void Method1() final {}

  // 派生クラスでオーバーライドできる通常のメソッド
  void Method2() {}
}

// 抽象クラス
abstract class MyAbstractBase {}
```

クラスを派生させる際に、メソッドが継承された基底クラスのメソッドをオーバーライドすることを意図していることをコンパイラに伝えることができます。これを行い基底クラスに一致するメソッドがない場合、コンパイラはエラーを発行します。これは基底クラスが変更されるが、派生クラスを更新するのを忘れてしまう可能性がある大規模なプロジェクトでエラーを捕捉するのに特に有用です。

```angelscript
class MyBase
{
  void Method() {}
  void Method(int) {}
}

class MyDerived : MyBase
{
  void Method() override {}      // OK。メソッドは基底クラスのメソッドをオーバーライドしています
  void Method(float) override {} // NG。メソッドは基底クラスのメソッドをオーバーライドしていません
}
```

## プロテクトとプライベートなクラスメンバー (Protected and private class members)

クラスのメンバーはアクセスできる場所を制御するために `protected` または `private` として宣言できます。プロテクトされたメンバーはクラスの外からアクセスできません。プライベートなメンバーはさらに、派生クラスからもアクセスできません。

```angelscript
// プライベートなメンバーを持つクラス
class MyBase
{
  // 以下はパブリックなメンバーです
  void PublicFunc()
  {
    // クラスは自身のプロテクトとプライベートなメンバーにアクセスできます
    ProtectedProp = 0; // OK
    ProtectedFunc();   // OK
    PrivateProp = 0;   // OK
    PrivateFunc();     // OK
  }   

  int PublicProp;

  // 以下はプロテクトなメンバーです
  protected void ProtectedFunc() {}
  protected int ProtectedProp;

  // 以下はプライベートなメンバーです
  private void PrivateFunc() {} 
  private int PrivateProp;
}

class MyDerived : MyBase
{
  void Func()
  {
    // 派生クラスは基底クラスのプロテクトなメンバーにアクセスできますが、
    // プライベートなメンバーにはアクセスできません
    ProtectedProp = 1; // OK
    ProtectedFunc();   // OK
    PrivateProp = 1;   // エラー
    PrivateFunc();     // エラー
  }
}
```

## クラスメンバーの初期化 (Initialization of class members)

クラスメンバーが初期化される順序は、継承を使用する場合やメンバーの初期化を宣言に直接定義する場合に重要になります。初期化前にメンバーにアクセスすると、スクリプトの実行を中断する null ハンドルアクセス例外が発生する可能性があります。

単純なクラスの場合、メンバーが初期化される順序はそれらが宣言された順序と同じです。メンバーの宣言に明示的な初期化が与えられている場合、これらのメンバーは最後に初期化されます。

継承が使用される場合、明示的な初期化がない派生クラスのメンバーは基底クラスのメンバーの前に初期化され、明示的な初期化があるメンバーは基底クラスのメンバーの後に初期化されます。

:::message
コンストラクタや初期化がクラスのメソッドを呼び出す場合に注意してください。クラスのメソッドは派生クラスでオーバーライドできるため、基底クラスが派生クラスのメンバーが初期化される前に誤ってアクセスしてしまう可能性があります。
:::
