## プリミティブ型 (Primitives)

AngelScript のプリミティブ型（基本型）には、C++ の各型と直接対応するものがあります。

| AngelScript | C++                  | サイズ (ビット) |
|-------------|----------------------|----------------|
| void        | void                 | 0              |
| int8        | signed char          | 8              |
| int16       | signed short         | 16             |
| int         | signed int (*)       | 32             |
| int64       | signed int64_t       | 64             |
| uint8       | unsigned char        | 8              |
| uint16      | unsigned short       | 16             |
| uint        | unsigned int (*)     | 32             |
| uint64      | unsigned uint64_t    | 64             |
| float       | float                | 32             |
| double      | double               | 64             |
| bool        | bool                 | 8 (\*\*)      |

(*) C++ における `int` 型はプラットフォームによってサイズが異なる可能性がありますが、現代の環境では 32ビットが一般的です。AngelScript では常に 32ビット固定として扱われます。

(**) 32ビット PowerPC プラットフォームでは、`bool` 型は一般的に 32ビットのサイズを持ちます。そのようなプラットフォーム向けにコンパイルされた場合、AngelScript も `bool` 型に 32ビットを使用します。

## 文字列 (Strings)

AngelScript は、アプリケーションが独自の[文字列型を登録](./doc_strings)することを想定して設計されています。そのため、登録された型がそのままスクリプト内での文字列型として機能し、両者は完全に一致します。

C++ で広く使われる `char*` による文字列ポインタは、スクリプト環境のような動的なメモリ管理下では所有権の扱いが非常に複雑になるため、そのまま扱うのは不向きです。そのため、`char*` を使用する関数はラップし、`std::string` などのアプリケーションとスクリプトエンジンの双方が安全かつ容易に扱えるオブジェクトへと適切に変換してやり取りすることを強く推奨します。

## 配列 (Arrays)

AngelScript はアプリケーションが [動的配列](./doc_arrays) に使用する型を登録することを期待しています。通常これは [Array アドオン](./doc_addon#配列-array) を登録することで行われますが、アプリケーションが別の方法を選択することも自由です。

異なる配列型に対して異なるオブジェクト型を持つことも可能であるため、アプリケーションは C++ で使用される型と配列型を正確に一致させることができます。

AngelScript における「オブジェクトハンドル」は、参照カウントによって管理されるオブジェクトへのポインタを指します。ハンドルを適切に機能させるには、対象となるオブジェクトが参照カウントを操作する手段（例：`AddRef`/`Release` メソッドのペア）を備えている必要があります。

AngelScript がオブジェクトハンドルを値渡しで関数に渡す際、引数として渡されるインスタンスの参照カウントをインクリメントします。そのため、呼び出し先の関数側は、処理が終了した時点でその参照を解放（Release）する責任を負います。同様に、関数から返されるハンドルについても、AngelScript はすでに参照カウントがインクリメントされた（所有権の移動が可能な）状態で返されることを期待します。

ただし、関数やメソッドを登録する際、ハンドルが渡されたり返されたりした後にライブラリ側で自動的に参照管理（インクリメントまたはデクリメント）を行うよう指定することも可能です。これは `@` 修飾子に `+` 記号を付与（例：`obj @+`）することで行われます。これにより、明示的な参照管理を必要としない通常の C++ ポインタを期待する関数に対しても、オブジェクトハンドルを安全に受け渡すことができます。

AngelScript でのオブジェクトハンドルの操作構文は C++ の参照に似ていますが、ハンドルには `null` を代入でき、指し示す対象の変更（再代入）も可能です。

| AngelScript ハンドル          | C++ ポインタ               | C++ 参照               |
|------------------------------|---------------------------|------------------------|
| `obj @m_obj;`                | `obj *m_obj = nullptr;`   | n/a                    |
| `obj @m_obj = aReference;`  | `obj *m_obj = aReference;`| `obj &m_obj = *aReference;` |
| `m_obj = aValue;`            | `*m_obj = aValue;`        | `m_obj = aValue;`      |
| `@m_obj = aReference;`      | `m_obj = aReference;`     | n/a                    |
| `m_obj.callMe();`            | `m_obj->callMe();`        | `m_obj.callMe()`       |

参照: [アプリケーションへのオブジェクトハンドル](./doc_obj_handle)

## スクリプトクラスとインターフェース (Script classes and interfaces)

アプリケーションから見ると、スクリプトクラスとインターフェースはすべて [asIScriptObject](#asIScriptObject) 型として見えます。[asIScriptObject](#asIScriptObject) インターフェースには、スクリプトクラスまたはインターフェースの実際の型を特定したり、実際のオブジェクトインスタンスと対話したりするためのメソッドがあります。

参照: スクリプトクラスのインスタンスの使用に関しては [スクリプトクラスの使用](./doc_using_script_class) を参照してください。

## 関数ポインタ (Function pointers)

すべてのスクリプトの関数ポインタは、アプリケーションから [asIScriptFunction](#asIScriptFunction) 型として見えます。[asIScriptFunction](#asIScriptFunction) 型には、関数の名前、パラメータの型、戻り値の型などを取得するためのメソッドがあります。

AngelScript ではポインタの有効性を常に保証する必要があるため、関数の引数にオブジェクトの実体への参照を直接渡すとは限りません。代わりにオブジェクトのコピーを作成し、そのコピーへの参照を関数に渡す場合があります。もし出力用の参照としてマークされている場合、関数終了時にその内容がオリジナルのオブジェクトへ書き戻されます。

この特徴から、AngelScript のパラメータ参照は C++ の参照やポインタと概ね互換性がありますが、渡された参照のアドレスを関数外で保持して再利用することは避けてください。関数から戻った直後に、その参照先のオブジェクト（コピー）が破棄される可能性があるためです。

オブジェクトのアドレスを永続的に保持する必要がある場合は、参照ではなくオブジェクトハンドルを使用してください。

| 参照          | 説明 |
|--------------|------|
| `&in`        | 値のコピーが常に作成され、コピーへの参照が関数に渡されます。スクリプト関数ではこれは有用ではありませんが、アプリケーションで登録された関数との互換性のために維持されています。 |
| `const &in`  | 値のライフタイムが関数の実行中に有効であることが保証できる場合、真のオブジェクトへの参照が関数に渡されます。そうでない場合はコピーが作成されます。 |
| `&out`       | 初期化されていない値への参照が関数に渡されます。関数が返ると、その値が真の参照にコピーされます。引数の式は関数呼び出しの後にのみ評価されます。これは関数が複数の値を返すための最善の方法です。 |
| `const &out` | 関数が値を変更できないため、無意味です。 |
| `&inout`     | 真の参照が常に関数に渡されます。オブジェクトハンドルをサポートするオブジェクトのみがこの型で使用できます。これらは呼び出し中に常に生存していることが保証できるからです。 |
| `const &inout` | 参照されるオブジェクトは読み取り専用になります。 |

もしアプリケーションが C++ と同様に機能するパラメータ参照を望む場合は、[エンジンプロパティを設定する](./doc_adv_custom_options) ことで許可できます。
