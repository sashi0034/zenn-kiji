---
title: "カスタム文字列型 (Custom string type)"
---

ほぼすべてのアプリケーションは、何らかの形でテキスト文字列を操作するニーズを持っています。しかし、ほとんどのアプリケーションは非常に異なるニーズを持っており、また文字列型の表現方法も異なります。そのため、AngelScript にはアプリケーションが強制的に適応しなければならないような独自の組み込み文字列型は用意されておらず、代わりにアプリケーションが [独自の文字列型を登録](./doc_register_api) できるようになっています。

この記事では、文字列に関してスクリプト言語をアプリケーションのニーズに合わせカスタマイズするためのオプションを紹介します。もし AngelScript に独自の文字列型を使用させたくない場合やその必要がない場合は、標準アドオンである [std::string の登録](./doc_addon_std_string) を使用することをお勧めします。

## カスタム文字列型の登録 (Registering the custom string type)

スクリプト言語で文字列をサポートさせるには、まず文字列型をエンジンに [型として登録](./doc_register_type) しなければなりません。アプリケーションは任意の有効な型名を自由に使用でき、おそらく最も一般的に使用される名前は 'string' ですが、必ずしもそうである必要はありません。カスタム文字列型は、アプリケーション開発者の好みに応じて、値型または参照型のいずれかを選択することができます。

文字列型が登録されたら、アプリケーションはスクリプトが文字リテラル（文字列定数）を使用できるようにするために文字列ファクトリも提供しなければなりません。文字列ファクトリは [asIStringFactory](#asIStringFactory) インターフェースを実装し、[RegisterStringFactory](#asIScriptEngine::RegisterStringFactory) メソッドを使用して登録される必要があります。

文字列ファクトリは `asIStringFactory` インターフェースの3つのメソッドすべてを実装しなければなりません。[GetStringConstant](#asIStringFactory::GetStringConstant) メソッドは、コンパイラから生の文字列データを受け取り、その文字列を表すカスタム文字列オブジェクトへのポインタを返す必要があります。[ReleaseStringConstant](#asIStringFactory::ReleaseStringConstant) は、モジュールが破棄される時など、エンジンが文字列定数をもう必要としなくなった時に呼び出されます。[GetRawStringData](#asIStringFactory::GetRawStringData) は、バイトコードを保存する時や文字列定数のコピーを要求する時など、エンジンが生の文字列データを必要とした時に呼び出されます。

必須ではありませんが、同じ生の文字列データを伴う `GetStringConstant` への2回の呼び出しがあった場合、文字列ファクトリが両方の呼び出しで同じ文字列インスタンスのアドレスを返すように、文字列定数のキャッシングをアプリケーションで実装することが望ましいです。これにより、特にスクリプトが多くの場所で同じ文字列定数を使用する場合に、文字列定数を格納するために必要なメモリ量を削減できます。キャッシングを使用する場合、`ReleaseStringConstant` は同じオブジェクトに対する最後の呼び出しが終了した時にのみ文字列オブジェクトを解放しなければならないことに注意してください。

参照: [標準文字列アドオン](./doc_addon_std_string)

## Unicode か ASCII か (Unicode vs ASCII)

あなたのアプリケーションはテキストに Unicode を使用していますか、それともプレーンな ASCII を使用していますか？ もし Unicode を使用しているなら、スクリプトを UTF-8 でエンコードしたいと思うでしょう。AngelScript のコンパイラはこれをネイティブでサポートしています。デフォルトでは、AngelScript はスクリプトが UTF-8 でエンコードされていることを期待しますが、ASCII を好む場合は、エンジンを作成した直後にエンジンプロパティ [asEP_SCRIPT_SCANNER](#asEP_SCRIPT_SCANNER) を 0 に設定することでこれを無効にすることができます。

```cpp
// スクリプトコードの読み取りに ASCII スキャナを使用するようにエンジンを設定する
engine->SetEngineProperty(asEP_SCRIPT_SCANNER, 0);
```

もし Unicode を使用する場合は、文字列リテラルのための適切なエンコーディング（UTF-8 または UTF-16）も選択したいと思うでしょう。デフォルトでは AngelScript の文字列リテラルは UTF-8 でエンコードされますが、アプリケーションが UTF-16 を処理するように設計されている場合は、スクリプトをコンパイルする前にエンジンプロパティ [asEP_STRING_ENCODING](#asEP_STRING_ENCODING) を 1 に設定することでこれを変更したくなるはずです。

```cpp
// 文字列リテラルに UTF-16 エンコーディングを使用するようにエンジンを設定する
engine->SetEngineProperty(asEP_STRING_ENCODING, 1);
```

エンジンが新しい文字列を作成するために呼び出す [文字列ファクトリ](#asIScriptEngine::RegisterStringFactory) は、UTF-16 でエンコードされた文字列であっても文字列データのサイズを**バイト単位**で提供する点に注意してください。そのため、文字列内の文字数を取得するためにはサイズを2で割る必要があります。

## 複数行の文字列リテラル (Multiline string literals)

スクリプト言語自体に少し影響を与えるいくつかのオプションもあります。複数行のコードにまたがる文字列リテラルを許容する便利さが欲しい場合は、エンジンプロパティ [asEP_ALLOW_MULTILINE_STRINGS](#asEP_ALLOW_MULTILINE_STRINGS) を true に設定することでこれを有効にすることができます。これがない場合、コンパイラは文字列の終端の前に改行に遭遇するとエラーを出力します。

```cpp
// 改行を含む文字列リテラルを許可するようにエンジンを設定する
engine->SetEngineProperty(asEP_ALLOW_MULTILINE_STRINGS, true);
```

ソースファイルの改行コードのエンコーディングはスクリプトコンパイラによって変更されないため、ファイルがどのように保存されたかに応じて、異なる改行コードを使用した文字列が得られる可能性があることに注意してください。

[ヒアドキュメント文字列 (heredoc strings)](./doc_datatypes_strings) は、複数行のテキストセクションをサポートするように設計されているため、この設定の影響を受けません。

## 文字リテラル (Character literals)

デフォルトでは、AngelScript には C や C++ のような文字リテラル (単一文字の表現) がありません。文字列リテラルはダブルクォーテーション ( `"` ) またはシングルクォーテーション ( `'` ) のどちらで記述されていても同じ意味（文字列）を持ちます。これにより、ダブルクォーテーションを使用するとスクリプトコードが終了してしまう恐れがある XML ファイルや C/C++ ソースファイル内にスクリプトを埋め込むのが便利になります。

もしシングルクォーテーションで囲まれたリテラルが文字列ではなく単一の文字リテラルを意味するようにしたい場合は、エンジンプロパティ [asEP_USE_CHARACTER_LITERALS](#asEP_USE_CHARACTER_LITERALS) を true に設定することで対応できます。この設定により、コンパイラはシングルクォーテーションで囲まれたリテラルを最初の文字を表す整数値へと変換します。

```cpp
// 文字リテラルを使用するようにエンジンを設定する
engine->SetEngineProperty(asEP_USE_CHARACTER_LITERALS, true);
```

この場合、[asEP_SCRIPT_SCANNER](#asEP_SCRIPT_SCANNER) プロパティが非常に重要であることに注意してください。ASCII 文字は 0 から 255 までの値しか表現できないのに対し、Unicode 文字は 0 から 1,114,111 までの値を表現できるからです。
