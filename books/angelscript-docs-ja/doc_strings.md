---
title: "カスタム文字列型 (Custom string type)"
---

ほぼすべてのアプリケーションで、何らかの形でテキスト文字列を操作する必要があります。しかし、ほとんどのアプリケーションは非常に異なるニーズを持っており、文字列型の表現方法も異なります。そのため、AngelScript はアプリケーションが適応を強制されるような独自の組み込み文字列型を備えていません。代わりに、AngelScript はアプリケーションが[独自の文字列型を登録](./doc_register_api)することを許可しています。

この記事では、文字列に関するアプリケーションのニーズに合わせてスクリプト言語をカスタマイズするためのオプションについて説明します。AngelScript に独自の文字列型を使用させたくない、あるいはその必要がない場合は、標準アドオンの [std::string 登録](./doc_addon_std_string) を使用することをお勧めします。

## カスタム文字列型の登録

スクリプト言語で文字列をサポートするには、まず文字列型をエンジンに[型として登録](./doc_register_type)する必要があります。アプリケーションは任意の有効な型名を使用できます。必ずしも 'string' である必要はありませんが、おそらく最も一般的に使用される名前です。カスタム文字列型は、アプリケーション開発者の好みに応じて、値型または参照型のいずれかにすることもできます。

文字列型が登録されたら、スクリプトがリテラル文字列定数を使用できるように、アプリケーションは文字列ファクトリも提供する必要があります。文字列ファクトリは `asIStringFactory` インターフェースを実装し、`asIScriptEngine::RegisterStringFactory` メソッドで登録する必要があります。

文字列ファクトリは、`asIStringFactory` インターフェースの3つのメソッドすべてを実装する必要があります。`GetStringConstant` メソッドはコンパイラから生の文字列データを受け取り、その文字列を表すカスタム文字列オブジェクトへのポインタを返す必要があります。`ReleaseStringConstant` は、モジュールを破棄するときなど、エンジンが文字列定数を必要としなくなったときに呼び出されます。`GetRawStringData` は、バイトコードを保存するときや文字列定数のコピーを要求するときなど、生の文字列データが必要なときにエンジンによって呼び出されます。

必須ではありませんが、アプリケーションは文字列定数のキャッシュを実装することが望ましいです。これにより、同じ生の文字列データで `GetStringConstant` が2回呼び出された場合、文字列ファクトリが両方の呼び出しで同じ文字列インスタンスのアドレスを返すようになります。これにより、特にスクリプトが多くの場所で同じ文字列定数を使用する場合に、文字列定数を格納するために必要なメモリ量を削減できます。キャッシュを使用する場合、`ReleaseStringConstant` は、その同じオブジェクトに対する最後の呼び出しが行われたときにのみ文字列オブジェクトを解放する必要があることに注意してください。

参照: [標準文字列アドオン](./doc_addon_std_string)

## Unicode vs ASCII

アプリケーションではテキストに Unicode とプレーン ASCII のどちらを使用していますか？Unicode を使用する場合、AngelScript コンパイラがネイティブにサポートしている UTF-8 でスクリプトをエンコードすることをお勧めします。デフォルトでは、AngelScript はスクリプトが UTF-8 でエンコードされていることを期待していますが、ASCII を好む場合は、エンジン作成直後にエンジンプロパティ `asEP_SCRIPT_SCANNER` を 0 に設定することで、これをオフにできます。

```cpp
// スクリプトコードに ASCII スキャナを使用するようにエンジンを設定します
engine->SetEngineProperty(asEP_SCRIPT_SCANNER, 0);
```

Unicode を使用する場合は、文字列リテラルのエンコードを UTF-8 または UTF-16 のいずれかから選択することもできます。デフォルトでは、AngelScript の文字列リテラルは UTF-8 でエンコードされていますが、アプリケーションが UTF-16 に適している場合は、スクリプトをコンパイルする前にエンジンプロパティ `asEP_STRING_ENCODING` を 1 に設定して変更できます。

```cpp
// 文字列リテラルに UTF-16 エンコードを使用するようにエンジンを設定します
engine->SetEngineProperty(asEP_STRING_ENCODING, 1);
```

エンジンから新しい文字列を作成するために呼び出される文字列ファクトリは、UTF-16 エンコードされた文字列であっても文字列データのサイズをバイト単位で提供するため、文字列内の文字数を取得するにはサイズを 2 で割る必要があることに注意してください。

## 複数行の文字列リテラル

スクリプト言語自体に少し影響を与えるオプションもいくつかあります。文字列リテラルがコードの複数行にまたがることを許可したい場合は、エンジンプロパティ `asEP_ALLOW_MULTILINE_STRINGS` を true に設定することでオンにできます。これがないと、コンパイラは文字列の終了前に改行に遭遇した場合にエラーを出力します。

```cpp
// 改行を含む文字列リテラルを許可するようにエンジンを設定します
engine->SetEngineProperty(asEP_ALLOW_MULTILINE_STRINGS, true);
```

ソースファイルの改行コードのエンコードはスクリプトコンパイラによって変更されないため、ファイルの保存方法によっては、異なる改行コードを使用した文字列が生成される可能性があることに注意してください。

[ヒアドキュメント文字列](./doc_datatypes_strings) は、複数行のテキストセクションをサポートするように設計されているため、この設定の影響を受けません。

## 文字リテラル

デフォルトでは、AngelScript には C や C++ のような文字リテラルはありません。文字列リテラルはダブルクォートまたはシングルクォートで記述でき、同じ意味を持ちます。これにより、ダブルクォートがスクリプトコードを終了させてしまうような XML ファイルや C/C++ ソースファイルにスクリプトを埋め込むのに便利です。

シングルクォートのリテラルを文字列ではなく単一の文字リテラルとして扱いたい場合は、エンジンプロパティ `asEP_USE_CHARACTER_LITERALS` を true に設定することで可能です。コンパイラは、シングルクォートのリテラルを最初の文字を表す整数に変換します。

```cpp
// 文字リテラルを使用するようにエンジンを設定します
engine->SetEngineProperty(asEP_USE_CHARACTER_LITERALS, true);
```

この場合、`asEP_SCRIPT_SCANNER` プロパティが重要になります。ASCII 文字は 0 から 255 の間の値しか表現できませんが、Unicode 文字は 0 から 1,114,111 の間の値を表現できるためです。
