## typeid の構造

AngelScript インターフェースのいくつかの関数で使用される typeid は、32ビットの符号付き整数です。負の値は有効な typeid ではなく、typeid を返す関数は負の値を使用して[エラーを示す](./doc_register_api#戻り値)ことができます。

typeid に含まれる値は2つの部分で構成されています。`asTYPEID_MASK_SEQNBR` で示される下位ビットは、アプリケーションによって登録された新しい型やスクリプトで宣言された新しい型ごとにインクリメントされるシーケンスです。上位ビットは、型のカテゴリを示すビットマスクを形成します。ビットマスクの各ビットには以下の意味があります：

- `asTYPEID_APPOBJECT` ビット: 型はアプリケーションで登録されたオブジェクトです。
- `asTYPEID_SCRIPTOBJECT` ビット: 型はスクリプトで宣言された型です。つまり、オブジェクトは `asIScriptObject` にキャストできます。
- `asTYPEID_TEMPLATE` ビット: 型はテンプレートであり、インスタンス化できません。
- `asTYPEID_HANDLETOCONST` ビット: 型は const オブジェクトへのハンドルです。つまり、参照されるオブジェクトを変更してはいけません。
- `asTYPEID_OBJHANDLE` ビット: 型はオブジェクトハンドルです。つまり、実際のオブジェクトのアドレスを取得するには値をデリファレンスする必要があります。
- 32ビット目: typeid は無効であり、数値はエラーコードを示します。

typeid がプリミティブであるかどうかを識別するには、`asTYPEID_MASK_OBJECT` のビットがゼロであることを確認してください。これは、すべての組み込みプリミティブ型と列挙型に当てはまります。

組み込みプリミティブ型には、`asETypeIdFlags` 列挙型で見られるように定義済みの ID があり、その値を直接比較できます（例: 32ビット符号付き整数の typeid は `asTYPEID_INT32` です）。

型に関する詳細情報（正確なオブジェクト型など）を取得するには、`asIScriptEngine::GetTypeInfoById` を使用してください。これにより `asITypeInfo` が返され、型に関するすべての詳細を取得できます。

## 呼び出し規約

仮想マシン内の AngelScript で使用される内部呼び出し規約は非常に単純です。

すべての関数引数は、最後から最初の順にスタックにプッシュされます。すべての引数は4バイトの境界にアラインされます。参照は CPU アーキテクチャに応じて4バイトまたは8バイトになります。プリミティブの値渡しはそのままプッシュされます。オブジェクトの値渡しは、オブジェクト自体がヒープに格納されている間、オブジェクトへの参照がスタックにプッシュされます。呼び出された関数は、オブジェクトをクリーンアップしてメモリを解放する責任があります。オブジェクトハンドルの場合、呼び出し側は引数が準備されるときに参照カウントを増やし、ハンドルをスタックにプッシュします。ハンドルの所有権は呼び出された関数に引き継がれ、関数は戻る前にそれを解放しなければなりません。

可変引数型 `?` は、実際の引数ラベルの前に typeid がスタックにプッシュされます。

関数が可変長引数 `...`（任意の実引数を受け入れる）の場合、実引数の数は最初の関数引数の後にスタックにプッシュされます。

関数がオブジェクトを値で返す場合、戻り値のオブジェクトを初期化する必要があるアドレスを持つ隠し引数がスタックにプッシュされます。返されたオブジェクトは、制御が呼び出し元に戻るまで呼び出された関数によって所有されます。つまり、オブジェクトが初期化されてから制御が呼び出し元に戻るまでの間に例外が発生した場合、例外ハンドラーは呼び出された関数のコールフレームの一部として、返されたオブジェクトをクリーンアップします。

関数がクラスメソッドの場合、オブジェクトインスタンスのアドレスが最後の引数としてスタックにプッシュされます。これにより、呼び出された関数は `this` ポインタが常にスタックフレームのポジション 0 にあることを保証できます。
