## typeid の構造

AngelScript の各 API で使用される typeID（型 ID）は、32 ビットの符号付き整数型です。負の値は型 ID としては無効であり、エラー状態（登録失敗など）を示すために使用されます。

typeID の値は 2 つのパートで構成されています。`asTYPEID_MASK_SEQNBR` で示される下位ビットは、アプリケーションでの登録やスクリプト内での宣言によって新しい型が定義されるたびにインクリメントされるシーケンス番号です。上位ビットは、型のカテゴリを示すビットマスクとなっています。各フラグビットの役割は以下の通りです：

- `asTYPEID_APPOBJECT` ビット: 型はアプリケーションで登録されたオブジェクト型です。
- `asTYPEID_SCRIPTOBJECT` ビット: 型はスクリプトで宣言された型です。このオブジェクトは `asIScriptObject` にキャスト可能です。
- `asTYPEID_TEMPLATE` ビット: 型はテンプレートであり、そのままではインスタンス化できません。
- `asTYPEID_HANDLETOCONST` ビット: 型は const オブジェクトへのハンドルです。参照先のオブジェクトを変更してはいけません。
- `asTYPEID_OBJHANDLE` ビット: 型はオブジェクトハンドルです。実際のオブジェクトのアドレスを取得するには、値をデリファレンスする必要があります。
- 31〜32ビット目（MSB）: 型 ID は無効であり、下位ビットの数値はエラーコードを示します。

特定の typeID がプリミティブ型（基本型）を指しているかどうかを判定するには、`asTYPEID_MASK_OBJECT` のビットがゼロであることを確認してください。これは、すべての組み込みプリミティブ型および列挙型（enum）に共通する特性です。

組み込みプリミティブ型には `asETypeIdFlags` 列挙型で定義された固定の ID が割り当てられており、直接比較が可能です（例：32 ビット符号付き整数の型 ID は `asTYPEID_INT32` です）。

型に関する詳細情報（正確なオブジェクト型など）を取得するには、`asIScriptEngine::GetTypeInfoById` を使用します。これにより `asITypeInfo` が取得でき、型の詳細なプロパティにアクセスできます。

## 呼び出し規約

仮想マシン内の AngelScript で使用される内部呼び出し規約は非常に単純です。

すべての関数引数は、最後から最初の順にスタックへプッシュされます。各引数は 4 バイト境界にアラインされます。参照（ポインタ）のサイズは CPU アーキテクチャに依存し、4 バイトまたは 8 バイトになります。プリミティブ型の値渡しはそのままスタックに積まれます。オブジェクトの値渡し（Pass-by-value）では、オブジェクトの実体はヒープ上に確保され、スタックにはそのオブジェクトへの参照がプッシュされます。この場合、呼び出し先の関数側にオブジェクトを破棄・解放する責任があります。オブジェクトハンドルの場合、呼び出し側が引数の準備段階で参照カウントをインクリメントした上でスタックに積み、その所有権（Ownership）を呼び出し先の関数に譲渡します。関数は制御を戻す前に、そのハンドルを適切に解放（Release）しなければなりません。

可変引数型 `?` では、実際の引数データの前にその typeid がスタックにプッシュされます。

関数が可変長引数 `...`（任意個の引数）を受け取る場合、引数の個数が最初の引数の後に続けてプッシュされます。

オブジェクトを値で返す関数の場合、戻り値となるオブジェクトを初期化すべきメモリ番地を示す隠し引数がスタックに渡されます。返されるオブジェクトは、制御が呼び出し元に戻るまでは呼び出された関数によって所有されます。つまり、オブジェクトの初期化から関数終了までの間に例外が発生した場合、例外ハンドラーは呼び出し関数のコールフレームの一部として、その戻り値用オブジェクトを適切に回収します。

クラスメソッド（メンバ関数）の場合、オブジェクトのインスタンスのアドレス（`this` ポインタ）が最後の引数としてプッシュされます。これにより、関数側では常にスタックフレームの先頭（位置 0）に `this` ポインタが存在することを前提として動作できます。
