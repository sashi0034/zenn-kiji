---
title: "ジェネリックなハンドル型の登録 (Registering a generic handle type)"
---

オブジェクトに特定の実装を強制することなく、オブジェクトへの参照を取得できると便利な場合があります。例えば、スクリプトにジェネリックなストレージクラスを提供する場合や、ジェネリックなメッセージングシステムを提供する場合などです。

AngelScript には、すべてのオブジェクト型に共通の分母（基底）は存在しません。その理由は、スクリプトクラスとアプリケーションから登録されたクラスでは実装が全く異なり、単一のスーパークラスの下に一般化することができないからです。

その代わり、AngelScript はアプリケーションがジェネリックなハンドル型を登録できるようにすることで代替案を提供しています。この型はアプリケーションのニーズに応じて実装されることになりますが、スクリプトからは任意の参照型を参照できるジェネリックな [ハンドル](./doc_script_handle) であるかのように見えます。これにより、この型はオブジェクト、[関数](./doc_datatypes_funcptr)、および [配列](./doc_addon_array) を保持できるようになります。

ジェネリックなハンドル型を登録するには、アプリケーションはいくつかの細かい点を除き、[値型](./doc_register_val_type) と同じ原則に従うべきです。それらの詳細について以下に説明します。

 - この型は、追加のフラグ [asOBJ_ASHANDLE](#asOBJ_ASHANDLE) を伴って登録されなければなりません。これが AngelScript に対して、この型がジェネリックなハンドルをシミュレートしていることを伝えるフラグです。

 - 任意のハンドルをこの型に代入できるようにするためには、[opHndlAssign](./doc_script_class_ops) メソッドが [可変パラメータ型](./doc_adv_var_type) で登録されなければなりません（例：`ref &opHndlAssign(const ?&in)`）。
 
 - `is` と `!is` の演算子がハンドルの期待通りに振る舞うことを可能にするために、[opEquals](./doc_script_class_ops) メソッドも [可変パラメータ型](./doc_adv_var_type) で登録されなければなりません（例：`bool opEquals(const ?&in)`）。
 
 - 最後に、任意の他の型への動的キャストを可能にするために、[opCast](./doc_script_class_ops) は `void opCast(?&out)` というシグネチャで登録されなければなりません。

これが非常に便利な型でありながらカスタマイズの必要性がほとんどないため、この実装を備えた標準アドオンが SDK に同梱されています。
