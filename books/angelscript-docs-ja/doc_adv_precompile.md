---
title: "事前コンパイル済みバイトコード (Pre-compiled byte code)"
---

スクリプトをロードするたびにソースコードからビルドする代わりに、事前コンパイル済みのバイトコード (Bytecode) を使用するのが有効な場合があります。これにより、ロード時間が短縮されるほか、ネットワーク経由でスクリプトを転送する場合には、ファイルサイズの大きなスクリプトの転送コストを削減できます。

コンパイル済みのコードを保存するには、`asIScriptModule` の `SaveByteCode` メソッドを呼び出し、`asIBinaryStream` インターフェースを実装したオブジェクトへのポインタを渡します。スクリプトモジュールは、`Write` メソッドを使用してすべてのバイトコードと関連データをこのストリームオブジェクトに書き込みます。

事前コンパイル済みバイトコードをロードする際は、まず新しいスクリプトをコンパイルするときと同様に `asIScriptModule` のインスタンスを取得します。その後、`AddScriptSection` や `Build` を呼び出す代わりに `LoadByteCode` メソッドを呼び出し、バイナリストリームオブジェクトへのポインタを渡します。スクリプトモジュールは、`Read` メソッドを使用してそのオブジェクトからすべてのバイトコードと関連データを読み取り、モジュールを再構築します。

以下は、`asIBinaryStream` インターフェースを実装する方法の非常に簡単な例です：

```cpp
class CBytecodeStream : public asIBinaryStream
{
public:
  CBytecodeStream(FILE *fp) : f(fp) {}

  void Write(const void *ptr, asUINT size) 
  {
    if( size == 0 ) return; 
    fwrite(ptr, size, 1, f); 
  }
  void Read(void *ptr, asUINT size) 
  { 
    if( size == 0 ) return; 
    fread(ptr, size, 1, f); 
  }

protected:
  FILE *f;
};
```

参照: [asbuild サンプル](./doc_samples#generic-compiler（汎用コンパイラ）)

## 覚えておくべきこと (Things to remember)

- **登録内容の整合性**: バイトコードを保存した際に使用されたすべてのオブジェクト、メソッド、プロパティ等は、ロードする際にも全く同じように登録されていなければなりません。不一致があると、正しい実体が見つからずロードに失敗します。

- **セキュリティの責任**: スクリプトエンジンは、ロードされる事前コンパイル済みバイトコードの妥当性検証を行いません。そのため、アプリケーション側でデータのソースが信頼できるものであることを保証する責任があります（デジタル署名など）。この確認を怠ると、悪意を持って改ざんされたバイトコードが実行され、セキュリティホールになる可能性があります。

- **オフラインコンパイル**: スクリプトをコンパイルするツールと、それを実行するアプリケーションが分かれている場合、コンパイル側では関数やメソッドの実体（関数ポインタ）を null で登録しても問題ありません。ただし、オブジェクトプロパティのオフセットなどは、実行環境と一致するように登録する必要があります。また、ビルド後にグローバル変数の初期化が走らないよう、`asIScriptEngine::SetEngineProperty` で `asEP_INIT_GLOBAL_VARS_AFTER_BUILD` を `false` に設定してください。[ヘルパーアドオン](./doc_addon#ヘルパー関数) には、オフラインコンパイラの構築を支援する関数が含まれています。
 
- **コンパイラの除外**: ソースコードからのコンパイルを行わず、事前コンパイル済みバイトコードのロードのみを行うアプリケーションでは、ライブラリを `AS_NO_COMPILER` マクロを定義してビルドすることで、実行ファイルのサイズを削減できます。
 
- **デバッグ情報のストリップ**: 保存されるバイトコードのサイズを小さくするために、デバッグ情報を除去（ストリップ）できます。これにより、スクリプトセクション名、行番号、ローカル変数の型や名前など、実行に必須ではない情報の保存を避けることができます。

- **共有エンティティと外部宣言**: スクリプトが [共有エンティティ](./doc_script_shared) を使用している場合、それらを [外部 (external)](./doc_script_shared#外部共有エンティティ-(external-shared-entities)) として宣言することで、保存されるバイトコードのサイズをさらに削減できます。この場合、オフラインコンパイラ側であらかじめそれらの共有エンティティを含む別のモジュールをビルドしておかなければなりません。

- **プラットフォームの互換性**: 保存されるバイトコードは基本的にプラットフォームに依存しません。ただし、ごく稀に影響を与える例外として、1) プリミティブ型のサイズ（例：古い Mac PPC 上の `bool`）と、2) CPU の浮動小数点表現（IEEE 754 かどうか）があります。ポインタサイズ（32bit vs 64bit）、CPU のエンディアン、登録された型のサイズやプロパティのオフセットの違いなどは、ライブラリによって適切に吸収されます。

- **バージョン間の互換性**: バイトコードは、AngelScript ライブラリの異なるバージョン間での互換性が保証されていません。保存時とロード時で、必ず同じバージョンのライブラリを使用してください。
