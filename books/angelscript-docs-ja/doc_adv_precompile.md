---
title: "事前コンパイル済みバイトコード (Pre-compiled byte code)"
---

スクリプトがロードされるたびにスクリプトを再ビルドする代わりに、事前コンパイル済みのバイトコードを使用することが役立つ場合があります。これにより、ロード時間を短縮できるほか、ネットワーク越しにスクリプトが転送される場合には、大きなスクリプトの転送時間を減らすことができます。

すでにコンパイルされているコードを保存するには、`asIScriptModule` の `SaveByteCode` メソッドを呼び出し、`asIBinaryStream` インターフェースを実装したオブジェクトへのポインタを渡します。その後、スクリプトモジュールはすべてのバイトコードと関連データを、`Write` メソッドを使用してこのオブジェクトへとプッシュします。

事前コンパイル済みバイトコードをロードする際は、まず新しいスクリプトをコンパイルする時と同じように `asIScriptModule` のインスタンスを取得する必要があります。`AddScriptSection` に続けて `Build` を呼び出す代わりに、`LoadByteCode` メソッドを呼び出し、バイナリストリームオブジェクトへのポインタを渡します。スクリプトモジュールはその後、`Read` メソッドを使用してそのオブジェクトからすべてのバイトコードと関連データをプルし、スクリプトモジュールを再構築します。

以下は、`asIBinaryStream` インターフェースを実装する方法の非常に簡単な例です：

```cpp
class CBytecodeStream : public asIBinaryStream
{
public:
  CBytecodeStream(FILE *fp) : f(fp) {}

  void Write(const void *ptr, asUINT size) 
  {
    if( size == 0 ) return; 
    fwrite(ptr, size, 1, f); 
  }
  void Read(void *ptr, asUINT size) 
  { 
    if( size == 0 ) return; 
    fread(ptr, size, 1, f); 
  }

protected:
  FILE *f;
};
```

## 覚えておくべきこと (Things to remember)

 - バイトコードをコンパイルする際に使用されたすべてのオブジェクト、メソッド、プロパティ等は、事前コンパイル済みバイトコードをロードする際にも登録されていなければなりません。そうでない場合、正しいエンティティが見つからずロードは失敗します。
 
 - スクリプトエンジンは事前コンパイル済みバイトコードの検証を行わないため、アプリケーションがソース（出所）の認証を行う責任を負っています。もしアプリケーションによってこの認証が行われない場合、バイトコードが不正なタスクを実行するために手作業で巧みに改ざんされている可能性があり、アプリケーションの潜在的なセキュリティリスクとなります。
  - スクリプトコードをコンパイルするアプリケーションと、それらを実行するアプリケーションが別個である場合、実際にはすべての関数やメソッドを実装する必要がないように、それらを null ポインタを用いて登録することができます。オブジェクトプロパティは、バイトコードローダーによって区別できるように異なるオフセットで登録されなければなりません。また、スクリプトがビルドされた後にスクリプトエンジンがグローバル変数の初期化を試みないように、`SetEngineProperty` でエンジンプロパティ `asEP_INIT_GLOBAL_VARS_AFTER_BUILD` を `false` に設定すべきです。[Helper アドオン](./doc_addon#ヘルパー関数-helper-functions) には、オフラインコンパイラの構築を容易にするためのいくつかの関数が含まれています。
 
 - アプリケーションがソースコードからスクリプトをコンパイルせず、単に事前コンパイル済みのスクリプトのロードのみを行う場合、実行可能ファイルのサイズを削減するために、ライブラリを `AS_NO_COMPILER` 定義付きでコンパイルすることが有益である可能性があります。
 
 - 保存されるバイトコードのサイズを削減するために、コードからデバッグ情報をストリップ（除去）することができます。これにより、スクリプトの実行には必要のない情報（スクリプトセクションの名前、行番号、ローカル変数の名前と型など）の保存がスキップされます。
 
 - スクリプトが [共有エンティティ](./doc_script_shared) を使用している場合、エンティティを [外部 (external)](./doc_script_shared_external) として宣言すれば、保存されるバイトコードのサイズをさらに削減できます。オフラインコンパイラが外部共有エンティティを用いたスクリプトをコンパイルできるようにするためには、オフラインコンパイラはまず、外部として宣言されることが許可されたすべての共有エンティティを含む別のモジュールをビルドしなければなりません。
 
 - 保存されるバイトコードはプラットフォームに依存しません。ただし、アプリケーション開発者に影響を与える可能性が低い例外が2つだけ存在します。その例外とは、1）プリミティブ型のサイズの違い（例：古い Mac PPC プラットフォーム上の `bool`）および 2）CPUの浮動小数点表現（つまり、IEEE 754 か 非IEEE 754 か）です。ポインタサイズ（32ビット対64ビット）、CPUのエンディアン、登録された型の異なるサイズ、および登録されたプロパティのオフセットの違いについてはすべて、プラットフォームの独立性を提供するために適切に処理されます。
 
 - 保存されるバイトコードは、異なるバージョンの AngelScript ライブラリ間で互換性が保証されているわけではないため、バイトコードを保存する時とそれをロードする時とで、必ず同じバージョンのライブラリを使用するようにしてください。
