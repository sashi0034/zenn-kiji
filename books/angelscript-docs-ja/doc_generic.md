---
title: "ジェネリック呼び出し規約 (The generic calling convention)"
---

ジェネリック呼び出し規約（Generic Calling Convention）は、アプリケーションのネイティブ呼び出し規約が利用できないプラットフォームや状況（例：新しい CPU アーキテクチャへの移植時など）で活用されます。ターゲットプラットフォームでネイティブ呼び出し規約がサポートされているか確認するには、`asGetLibraryOptions` 関数を呼び出し、返された文字列に "AS_MAX_PORTABILITY" が含まれているかを確認します。この文字列が含まれている場合、ネイティブな呼び出し規約はサポートされていません。

ジェネリック呼び出し規約を実装する関数は、`asIScriptGeneric` インターフェースへのポインタを引数として受け取り `void` を返す、常にグローバル関数（または静的クラスメソッド）の形式をとります。

```cpp
// この関数は以下のシグネチャで登録されています：
//  MyIntf @func(int, float, MyIntf @+)
void MyGenericFunction(asIScriptGeneric *gen)
{
  // 引数を抽出する
  int arg0              = gen->GetArgDWord(0);
  float arg1            = gen->GetArgFloat(1);
  asIScriptObject *arg2 = reinterpret_cast<asIScriptObject*>(gen->GetArgObject(2));
  
  // 実際の関数を呼び出す
  asIScriptObject *ret = MyFunction(arg0, arg1, arg2);
  
  // 戻り値を設定する
  gen->SetReturnObject(ret);
}
```

ジェネリック呼び出し規約を使用する関数は、スクリプトエンジンがグローバル関数またはクラスメソッドを期待する場所であればどこでも登録することができます（明示的に別段の指定がある場合を除きます）。

ジェネリック呼び出し規約用の関数を記述するには、AngelScript のスタックから各引数を抽出し、その後に手動で戻り値を設定する必要があります。そのため、自分で関数を記述するよりも、[自動ラッパー](./doc_addon#自動ラッパー関数) アドオンを使用する方が望ましい場合があります。

## 関数の引数の抽出 (Extracting function arguments)

ジェネリックなインターフェースから引数を抽出するには、各データ型に対応した `GetArg` メソッド、または `GetAddressOfArg` メソッドを使用します。`GetAddressOfArg` は引数の値が格納されているメモリのアドレスを返します。アプリケーションは、このポインタを適切な型にキャストして値を読み取ります。

実装する関数がクラスメソッド（メンバ関数）である場合、対象となるオブジェクトのインスタンスへのポインタは `GetObject` を呼び出すことで取得できます。

出力参照（`&out`）を受け取る引数の場合、`GetAddressOfArg` はその型の有効なインスタンスのアドレスを返します。関数側で何も値を返したくない場合は、特に操作を行う必要はありません。

`asIScriptGeneric` インターフェースにおける参照カウントの扱いは、ネイティブ呼び出し規約と同じです。つまり、ハンドルとして引数を受け取った場合（`@+` [自動ハンドル](./doc_obj_handle#自動ハンドルによる管理の簡略化-(auto-handles-can-make-it-easier)) を使用して登録している場合を除き）、アプリケーション側でその参照を解放する責任があります。

関数から値を戻すには、`SetReturn` メソッドのいずれかを使用して値をジェネリックインターフェースに渡します。プリミティブ型の返却は単純ですが、オブジェクト型を値渡し、参照渡し、またはオブジェクトハンドルとして返す場合は注意が必要です。型や使用するメソッドに応じて、事前に参照カウントをインクリメントしたり、あるいはオブジェクトのコピーを作成したりする必要があります。期待通りの結果を得るために、`SetReturnAddress` および `SetReturnObject` の説明を注意深く読んでください。

`GetAddressOfReturnLocation` メソッドを使用して、戻り値が保存されるメモリのアドレスを取得することも可能です。このメモリは初期化されていないため、placement new 演算子を使用してコンストラクタを呼び出し、このメモリを初期化する必要があります。これはプリミティブ型に対しても機能するため、[自動ラッパー](./doc_addon#自動ラッパー関数) などのテンプレート実装において理想的です。

戻り値の型がハンドルである場合、`GetAddressOfReturnLocation` は null ポインタが格納されているメモリ領域を指します。そのため、関数が null を返す場合は特に追加の操作は不要です。プリミティブの場合、それは未定義の値になるため、値が重要であれば明示的に設定しなければなりません。呼び出し元の関数によってすでに事前割り当てされた場所で返される値型のオブジェクトの場合、`SetException` で例外が設定されていない限り、関数はその場所で戻り値を初期化しなければなりません。

関数が `@+` を返すように登録されている場合、ネイティブな呼び出し規約のために行われるのと同様に、スクリプトエンジンは [自動的に参照カウントをインクリメント](./doc_obj_handle#自動ハンドルによる管理の簡略化-(auto-handles-can-make-it-easier)) します。
