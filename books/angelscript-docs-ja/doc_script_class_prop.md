title: "プロパティアクセサー (Property accessors)"
---

:::message
アプリケーションはプロパティアクセサーのサポートを [オプションでオフにする](./doc_adv_custom_options#言語の変更-language-modifications) ことができるため、お使いのアプリケーションでサポートされているかどうかをアプリケーションのマニュアルで確認してください。
:::

プロパティを操作する際、プロパティにアクセスする時に特定のロジックが確実に実行されるようにしなければならないことがよくあります。例えば、プロパティが変更された時に常に通知を送信したり、他のプロパティからプロパティの値を計算したりする場合です。プロパティのプロパティアクセサーメソッドを実装することで、これをクラス自身が実装でき、プロパティにアクセスする側が楽になります。

AngelScript のプロパティアクセサーは次の構文で宣言されます：

```cs
class MyObj
{
  // アクセサーを持つ仮想プロパティ
  int prop 
  { 
    get const 
    { 
      // プロパティの実際の値はどこか別の場所に格納されることも、
      // アクセス時に計算されることもあります
      return realProp; 
    } 
    set 
    { 
      // 新しい値は 'value' という名前の隠しパラメータに格納されます
      realProp = value; 
    }
  }

  // 実際の値はメンバーまたはどこか別の場所に格納できます
  // 望む場合は実際のプロパティに同じ名前を使用することも実際に可能です
  private int realProp;
}
```

内部では、コンパイラはこれをプロパティの名前とプレフィックス `get_` と `set_` を持つ2つのメソッドに変換し、関数デコレータ `property` を付けます。以下は同等のコードを生成し、これも完全に有効です：

```cs
class MyObj
{
  int get_prop() const property { return realProp; }
  void set_prop(int value) property { realProp = value; }
  private int realProp;
}
```

2つのメソッドを明示的に書いてプロパティアクセサーを実装する場合、get アクセサーの戻り値の型と set アクセサーのパラメータ型が一致していることを確認する必要があります。そうでないとコンパイラは使用する正しい型が分かりません。

インターフェースでは、最初の代替方法がプロパティアクセサーを宣言する好ましい方法です（コンパクトで読みやすいため）：

```cs
interface IProp
{
  int prop { get const; set; }
}
```

get または set アクセサーのどちらかを省略することもできます。set アクセサーを省略すると、プロパティは読み取り専用になります。get アクセサーを省略すると、プロパティは書き込み専用になります。

プロパティアクセサーはグローバルプロパティにも実装でき、同じルールが適用されますが、関数がグローバルになります。

プロパティアクセサーが宣言されると、通常のプロパティのようにそれらにアクセスすることができ、コンパイラはプロパティが式でどのように使用されるかに応じて、`set_` または `get_` 関数の適切な呼び出しに自動的に式を展開します。

```cs
void Func()
{
  MyObj obj;

  // 通常のプロパティのようにプロパティの値を設定します
  // コンパイラはこれを set_prop(10000) の呼び出しに変換します
  obj.prop = 10000;

  // 通常のプロパティのようにプロパティの値を取得します
  // コンパイラはこれを get_prop() の呼び出しに変換します
  assert( obj.prop == 1000 );
}
```

プロパティアクセサーは実際には値への直接アクセスではなくメソッドのペアであるため、同じ操作で検査と変更を行う式でどのように使用できるかについていくつかの制限があります。所有オブジェクトが参照型の場合、プロパティアクセサーに複合代入を使用できますが、値型の場合は使用できません。これは、コンパイラが get アクセサーと set アクセサーへの2つの呼び出しの間でオブジェクトが生存し続けることを保証できなければならないためです。

インクリメント・デクリメント演算子は現在サポートされていません。そのような場合、読み取りと書き込みの操作が別々に実行されるよう式を展開しなければなりません：

```cs
a++;     // a が仮想プロパティの場合は動作しません
a += 1;  // 仮想プロパティの所有者が参照型か、
         // プロパティがグローバルである限り OK です
```

## インデックス付きプロパティアクセサー (Indexed property accessors)

プロパティアクセサーは、単一のプロパティまたはインデックス演算子を通じてアクセスされるプロパティの配列をエミュレートするために使用できます。インデックス付きアクセスのプロパティアクセサーは通常のプロパティアクセサーと同じように機能しますが、インデックスの引数を取ります。get アクセサーはインデックス引数を唯一の引数として取り、set アクセサーはインデックス引数を最初の引数として取り、新しい値を2番目の引数として取ります。

```cs
string firstString;
string secondString;

// グローバルのインデックス付き get アクセサー
string get_stringArray(int idx) property
{
  switch( idx )
  {
  case 0: return firstString;
  case 1: return secondString;
  }
  return "";
}

// グローバルのインデックス付き set アクセサー
void set_stringArray(int idx, const string &in value) property
{
  switch( idx )
  {
  case 0: firstString = value; break;
  case 1: secondString = value; break;
  }
}

void main()
{
  // インデックス付きプロパティの値を設定します
  stringArray[0] = "Hello";
  stringArray[1] = "World";

  // インデックス付きプロパティの値を読み取ります
  print(stringArray[0] + " " + stringArray[1] + "\n");
}
```

複合代入は現在インデックス付きプロパティでは動作しません。
